# 提醒机制产品设计方案（V1）

[返回 README](../README.md) · [安装与排查](INSTALL.md) · [工具支持清单](DATA_SOURCES.md) · [路线图](ROADMAP.md)

> 文档状态：V1 已实现，视觉与系统通知仍需在真实安装应用中持续验收
> 最近更新：2026-09-11

## 1. 背景与目标

QuotaMonitor 已经可以展示 Codex 额度、DeepSeek 共享余额和本机 Token 用量。提醒能力的目标，是让用户不必持续盯着主面板，也能在资源接近风险线或当日用量跨过重要节点时及时得知。

V1 重点解决三个问题：

1. Codex 5 小时额度或周额度偏低时，及时提醒。
2. Codex / Claude 正在走 DeepSeek 路由、共享余额即将耗尽时，及时提醒。
3. 当日 Token 用量达到亿级里程碑时，让用户感知当天的高强度使用。

提醒只基于 QuotaMonitor 已经获取并确认可用的数据，不根据缺失、失败或过期数据推断风险；它也不会修改用户路由、兑换额度或充值余额。

## 2. V1 产品原则

- **默认有用：** 新安装默认开启额度与用量提醒及系统通知偏好；系统通知能否投递仍以 macOS 的实际授权为准，没有授权时回退到应用内提醒。
- **只提醒一次：** 同一风险周期不会因定时刷新反复弹出。
- **冷启动不漏报：** 用户打开应用并完成同步后，如果当前已经满足条件，立即提醒一次。
- **逐项清楚展示：** 同一轮同步同时命中多个事项时分别提醒，不合并标题或正文。
- **数据可信优先：** 只有对应数据源状态正常时才参与判断。
- **状态栏保持干净：** 提醒不在菜单栏图标上增加角标、红点或未读状态。

## 3. 提醒规则

| 提醒对象 | 触发条件 | 去重周期 | 恢复与再次提醒 |
| --- | --- | --- | --- |
| Codex 5 小时额度 | 官方 Codex 路由；数据源正常；界面显示的剩余比例 ≤ 30% | 同一个 5 小时额度窗口只提醒一次 | 服务返回新的重置时间后，视为新窗口，可再次提醒 |
| Codex 周额度 | 官方 Codex 路由；数据源正常；界面显示的剩余比例 ≤ 30% | 同一个周额度窗口只提醒一次 | 服务返回新的重置时间后，视为新窗口，可再次提醒 |
| DeepSeek 共享余额 | Codex 或 Claude 当前正在使用 DeepSeek；余额数据源正常；币种为 CNY；余额 < ¥5 | 低余额状态期间只提醒一次 | 余额恢复至 ≥ ¥6 后解除低余额状态；之后再次跌破 ¥5 时重新提醒 |
| 当日 Token | 至少一个 Token 数据源正常；本机自然日累计达到 1 亿、2 亿、3 亿…… | 每个自然日、每个整数亿级里程碑只提醒一次 | 次日按新的自然日重新从 1 亿开始计算 |

### 3.1 Codex 百分比口径

提醒使用与界面一致的百分比取整方式。用户在界面看到 `30%` 时即命中提醒，避免出现“页面显示 30%，提醒却没有触发”的认知差异。

如果额度数据没有重置时间，V1 会在持续低额度期间只提醒一次；额度回到 30% 以上后，该项才重新具备提醒资格。

### 3.2 DeepSeek 路由与余额口径

DeepSeek 余额是 Codex 和 Claude 共用的账户余额信号。只要任意一个产品当前识别为 DeepSeek 路由，低余额规则就生效；两者同时走 DeepSeek 时也只判断一次共享余额。

V1 的金额规则只适用于人民币余额。非 CNY 余额不会直接套用“低于 5 元”的阈值，以免单位不同造成误报。

设置 ¥6 的恢复线，是为了避免余额在 ¥5 附近波动时反复提醒：

```text
余额 < ¥5       → 触发一次并进入低余额状态
¥5 ≤ 余额 < ¥6  → 不重复提醒，也不解除状态
余额 ≥ ¥6       → 解除状态，下一次跌破 ¥5 可再次提醒
```

### 3.3 Token 里程碑口径

Token 规则使用用户 Mac 当前时区下的自然日累计值。若一次同步从 0.9 亿直接更新到 3.2 亿，只展示“已跨过 3 亿”，并将 1 亿、2 亿同时记为已处理，不连续补发三条提醒。

该指标代表本机已采集到的 Token 使用量，不等同于订阅剩余额度、账单金额或跨设备账户总量。

## 4. 触发时机与冷启动策略

提醒判断发生在额度、余额或 Token 数据完成一轮更新之后。应用只对新鲜可用的数据执行规则，刷新失败时不会把缺失值当成零。

用户当天已经使用了大量资源，再打开 QuotaMonitor 时，采用以下策略：

1. 应用启动并恢复已有缓存，但不基于尚未核实的数据抢先提醒。
2. 首轮额度与 Token 同步完成后执行规则判断。
3. 如果 Codex 只剩 20%、DeepSeek 余额低于 ¥5，或当天 Token 已到 3.2 亿，立即生成当前应有的提醒。
4. 已经跨过多个 Token 里程碑时只提醒最高里程碑。
5. 提醒记录写入本机，后续定时刷新和应用重启不会对同一周期重复弹出。

因此，冷启动提醒表达的是“同步后发现当前已经处于风险状态”，无需证明应用曾实时观察到从阈值上方跌到阈值下方的瞬间。

## 5. 多项同时触发策略

同一轮数据更新同时命中多个规则时，每个事项生成一条独立提醒：

- Codex 5 小时额度和周额度同时低于 30%：分别显示两条额度提醒。
- Codex 额度、DeepSeek 余额和 Token 里程碑同时命中：分别显示对应提醒，不使用“有多项资源提醒”一类合并文案。
- 使用系统通知时，每个事项创建一条独立的 macOS 通知；使用应用内提醒时，多张卡片在菜单栏下方纵向排列。
- 不同刷新轮次先后命中的事项仍分别提醒，不跨时间等待凑批次。

点击 Codex 额度或 DeepSeek 余额提醒进入“概览”，点击 Token 提醒进入“Token 看板”。V1 不增加提醒优先级队列，同一批次保持规则产出的稳定顺序：5 小时额度、周额度、DeepSeek 余额、Token 用量。

## 6. 通知渠道与降级逻辑

### 6.1 渠道选择

| 当前状态 | 提醒方式 |
| --- | --- |
| 用户开启系统通知，且 macOS 已授权 | 使用 macOS 原生通知横幅，并进入通知中心列表 |
| 系统通知关闭、未授权、被拒绝或投递失败 | 在菜单栏图标下方展示应用内提醒卡片 |

这套策略保证系统通知权限不是提醒功能的前置条件。系统通知的样式、停留时间、声音及是否长期保留，由 macOS 和用户的系统通知设置控制；QuotaMonitor 负责标题、正文和点击后的应用跳转。

### 6.2 应用内提醒视觉与位置

- 应用内提醒使用独立浮层，以菜单栏图标的水平中心为基准显示在图标下方，并限制在当前屏幕可见范围内。
- 卡片采用已确认的 A 版方案：使用 QuotaMonitor 官方应用图标、统一系统字体、加粗标题、常规正文、圆角卡片和轻量边框。
- 浮层背景保持透明，只显示卡片自身及原生阴影，卡片外围不得出现额外灰色包裹层。
- 每个提醒使用独立卡片；同批多项提醒纵向排列，卡片高度随正文适配。
- 点击正文打开对应页面；右上角关闭按钮只关闭当前卡片。
- 提醒出现、关闭或自动消失都不得改变菜单栏图标外观，也不保留未读角标。

## 7. 消失与打扰控制

| 场景 | 消失策略 |
| --- | --- |
| 真实应用内提醒 | 默认 8 秒后自动消失 |
| 鼠标停留在应用内提醒上 | 暂停倒计时；移开后重新开始倒计时 |
| 用户点击关闭 | 立即关闭当前提醒 |
| 用户点击提醒正文 | 关闭当前提醒，并打开对应页面 |
| macOS 系统通知 | 由系统通知设置决定；可在通知中心查看 |

应用内提醒不要求用户必须手动关闭。多项同时触发时，每张卡片独立展示并使用相同的 8 秒倒计时；鼠标停留只暂停当前卡片的倒计时。

## 8. 设置项设计

### 8.1 当前设置

1. **登录后自动启动**：新安装默认尝试开启；如果 macOS 要求确认，以“系统设置 → 通用 → 登录项与扩展”中的实际状态为准。该设置不改变提醒规则。
2. **额度与用量提醒**：总开关，新安装默认开启。关闭后停止规则判断，并关闭当前应用内提醒。
3. **系统通知**：新安装默认开启偏好，只有总开关开启时可操作。首次运行会请求 macOS 通知权限。

如果 macOS 拒绝通知权限，系统通知开关不能保持为开启状态，真实提醒自动回退到应用内渠道。用户需要在 macOS“系统设置 → 通知 → QuotaMonitor”中重新授权。

当前 V1 设置页没有保留测试提醒按钮；验收使用规则单元测试和受控数据触发，避免测试事件污染真实提醒的去重记录。

### 8.2 V1 为什么不开放规则自定义

V1 暂不提供自定义阈值、单项开关或提醒频率。固定规则便于验证“何时触发、是否重复、是否误报”这三个核心问题，也能避免设置页在首版变得过重。

后续只有在默认阈值确实不适合不同用户、且已有足够反馈时，再增加：

- 分规则启停；
- Codex 剩余百分比阈值；
- DeepSeek 余额阈值与币种策略；
- Token 里程碑步长；
- 提醒静默时段或稍后提醒。

## 9. 文案结构

提醒文案遵循“对象 + 当前状态 + 必要时间信息”的顺序：

| 类型 | 标题示例 | 正文示例 |
| --- | --- | --- |
| 5 小时额度 | Codex 5小时额度提醒 | 5小时额度剩余 28%，今天 16:30 重置 |
| 周额度 | Codex 周额度提醒 | 周额度剩余 18%，9月17日 23:07 重置 |
| DeepSeek | DeepSeek 余额提醒 | 余额仅剩 ¥4.20，请尽快续费 |
| Token | Token 用量提醒 | 今日累计已消耗 1.08亿 Token |

文案不使用“即将耗尽”等无法由固定阈值严格证明的强结论，也不把 Token 用量描述为费用。

## 10. 状态与边界处理

| 情况 | V1 行为 |
| --- | --- |
| 数据源正在扫描或刷新失败 | 不触发该数据源对应的提醒 |
| Codex 正在走 DeepSeek 路由 | 不判断 Codex 官方 5 小时 / 周额度；判断共享 DeepSeek 余额 |
| Claude 官方路由 | V1 没有可用的 Claude 官方额度提醒 |
| Codex 和 Claude 同时走 DeepSeek | 对共享余额只提醒一次 |
| 关闭提醒期间跨过阈值 | 不弹出；重新开启后，在下一轮有效同步时按当前状态判断 |
| 提醒后退出并重启应用 | 同一额度窗口、低余额状态或当日 Token 里程碑不重复提醒 |
| 系统权限后来被关闭 | 设置状态与系统授权同步，自动回退应用内提醒 |
| 多屏或菜单栏靠近屏幕边缘 | 应用内提醒优先居中对齐图标，同时避免超出当前屏幕可见区域 |

## 11. 验收方案

### 11.1 通知渠道验收

使用受控数据分别触发 Codex 5 小时额度、周额度、DeepSeek 余额和 Token 里程碑：

1. 关闭系统通知，检查应用内卡片的位置、官方图标、标题、正文、关闭按钮、悬停暂停、8 秒自动消失和点击跳转。
2. 开启系统通知并完成 macOS 授权，检查原生横幅的应用名、标题、正文以及点击后能否打开 QuotaMonitor。
3. 同一轮同时触发多个规则，确认系统通知逐条投递，应用内卡片逐条纵向排列，没有合并提醒。
4. 提醒出现、关闭和自动消失后，菜单栏图标都不得出现角标或白点。

### 11.2 规则验收清单

- 首次同步得到 30% 时提醒，31% 时不提醒。
- 首次同步直接得到 20% 时立即提醒；同一重置窗口后续刷新不重复。
- 5 小时和周额度同时低于 30% 时分别出现两条提醒。
- DeepSeek 路由关闭时，即使余额低于 ¥5 也不提醒。
- 余额从 ¥4.8 恢复到 ¥5.5 再跌到 ¥4.8 时不重复；恢复到 ¥6 后再跌破 ¥5 才重新提醒。
- Token 从 0.9 亿跳到 3.2 亿时只提醒 3 亿；次日达到 1 亿时可再次提醒。
- 系统通知未授权或投递失败时，仍能看到菜单栏应用内提醒。
- 应用内提醒 8 秒自动消失，悬停暂停，关闭后不留下菜单栏角标。
- 点击提醒进入正确页面。

真实应用视觉验收应覆盖浅色、深色、菜单栏靠近屏幕边缘和至少一种多屏布局。构建通过或单元测试通过不能代替这部分验收。

## 12. V1 暂不覆盖

- 用户自定义阈值、逐项开关和静默时段；
- 应用内提醒历史、逐条已读、稍后提醒；
- 邮件、短信、Webhook 或移动端推送；
- Claude 官方额度提醒；
- 非人民币 DeepSeek 余额的自动换算；
- 跨设备 Token 汇总后的提醒；
- 根据消耗速度预测“还能用多久”的主动提醒。

## 13. 后续迭代建议

建议按真实反馈逐步推进：

1. **V1.1 体验稳定性：** 完成系统通知与应用内卡片的真实安装验收，补充多屏、边缘位置、深浅色和系统拒绝权限场景。
2. **V1.2 提醒中心：** 若用户经常错过 8 秒弹层，再增加最近提醒列表和逐条已读，不急于先加更多通知渠道。
3. **V2 规则自定义：** 在默认规则验证稳定后，开放分项开关、阈值和静默时间，并提供恢复默认值。
4. **V2 数据扩展：** 只有 Claude 官方额度等数据源经过真实验证后，才新增对应提醒规则。
