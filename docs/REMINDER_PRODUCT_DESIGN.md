## 1. 目标

QuotaMonitor 在用户不持续盯着主面板的情况下，提醒以下变化：

1. Codex 5 小时额度和周额度进入 30% 或 5% 档位；
2. Codex 5 小时额度和周额度按时重置或提前重置；
3. 每个具有明确到期时间的 Codex 重置机会进入最后 24 小时；
4. DeepSeek 共享余额低于固定安全线；
5. 本机当日 Token 用量跨过整数亿级里程碑。

提醒只使用刚完成刷新且可以确认的数据。应用不会自动兑换重置机会、修改路由或充值余额。

## 2. 产品原则

- **分级提醒：** 30% 用于预警，5% 用于再次提醒；到 0% 不额外通知。
- **状态变化可感知：** 5 小时和周额度从低于 100% 恢复至 100% 时识别按时或提前重置；连续 100% 时只更新重置时间。
- **同一事件只提醒一次：** 定时刷新和应用重启不会重复投递同一档位、窗口或到期机会。
- **冷启动补发：** 首轮新鲜数据已处于低额度或 24 小时到期范围时立即提醒。
- **数据可信优先：** 扫描中、失败、过期、缺失或沿用旧缓存的数据不产生新事件。
- **渠道可降级：** 系统通知不可用时仍通过菜单栏下方的应用内卡片提醒。
- **离席保持静默：** 熄屏、锁屏和睡眠期间不投递或积压提醒，恢复后只判断最新的新鲜数据。
- **固定规则：** V1.1 继续使用一个总开关，不增加单项开关、自定义阈值或静默时段。

## 3. 提醒规则

| 提醒对象 | 触发条件 | 去重与恢复 |
| --- | --- | --- |
| Codex 5 小时额度 30% 档 | 官方路由、数据新鲜、界面显示值 ≤ 30% 且 > 5% | 同一个确认的补充周期一次；额度恢复后重新启用 |
| Codex 5 小时额度 5% 档 | 官方路由、数据新鲜、界面显示值 ≤ 5% | 同一个确认的补充周期一次；同时将 30% 档记为已处理 |
| Codex 周额度 30% 档 | 官方路由、数据新鲜、界面显示值 ≤ 30% 且 > 5% | 同一个确认的补充周期一次；额度恢复后重新启用 |
| Codex 周额度 5% 档 | 官方路由、数据新鲜、界面显示值 ≤ 5% | 同一个确认的补充周期一次；同时将 30% 档记为已处理 |
| 5 小时额度按时重置 | 上一条低于 100%，越过旧窗口结束时间后恢复至 100% | 每个旧窗口一次 |
| 5 小时额度提前重置 | 上一条低于 100%，在旧窗口结束前恢复至 100% | 每个旧窗口一次 |
| 周额度按时重置 | 上一条低于 100%，越过旧周窗口结束时间后恢复至 100% | 每个旧周窗口一次 |
| 周额度提前重置 | 上一条低于 100%，在旧周窗口结束前恢复至 100% | 每个旧周窗口一次 |
| 重置机会到期 | 当前刷新返回明确到期时间，且该机会剩余时间在 0～24 小时内 | 每个机会一次；多个机会逐个提醒 |
| DeepSeek 共享余额 | Codex 或 Claude 正在走 DeepSeek；余额新鲜、币种为 CNY、余额 < ¥5 | 低余额期间一次；恢复至 ≥ ¥6 后重新启用 |
| 当日 Token | 至少一个 Token 数据源正常；本机自然日累计达到 1 亿、2 亿、3 亿…… | 每个自然日、每个整数亿级里程碑一次 |

### 3.1 百分比与档位

提醒与界面使用同一四舍五入口径。界面显示 30% 或 5% 时分别命中对应档位，标题展示本轮实际显示值。

所有可着色界面使用同一档位：31%～100% 为正常，6%～30% 使用橙色需关注状态，0%～5% 使用红色高风险状态。5 小时额度和周额度遵循同一规则；重置时间只展示事实，不参与颜色或风险判断。应用内提醒用橙色和红色强调区分两档，系统通知在标题中写明等级。

```text
31% → 不提醒
28% → 触发 30% 档，标题显示“仅剩28%”
28% → 4% → 再触发 5% 档，标题显示“仅剩4%”
冷启动直接得到 4% → 只触发 5% 档，并把 30% 档记为已处理
5% → 0% → 不增加 0% 提醒
```

额度 30% / 5% 档位按已确认的补充周期保存已提醒状态。重置时间仅用于展示和辅助判断恢复，连续漂移不会重新触发；没有可信恢复证据时，已提醒状态保持不变。

### 3.2 5 小时与周额度重置识别

应用持久化上一条新鲜 Codex 观测，包括：

- 5 小时与周额度显示值；
- 5 小时与周额度重置时间；
- 5 小时与周窗口周期；
- 最近一次成功获取的重置机会数量；
- 观察时间。

任一额度重置必须同时满足：

1. 该指标上一条界面显示值低于 100%，当前恢复至 100%；
2. 该指标的新重置时间比旧重置时间至少推进 2 分钟；
3. 当前和上一条观测都来自官方 Codex 路由的新鲜额度数据；
4. 该旧窗口尚未生成或抑制过重置事件。

分类比较当前观察时间与旧计划重置时间：

```text
当前观察时间早于旧计划重置时间 2 分钟以上 → 提前重置
当前观察时间接近或晚于旧计划重置时间       → 按时重置
```

连续两条新鲜观测都显示 100% 时，即使服务端把下一次重置时间向后调整，也只更新基线。额度再次显示低于 100% 后，才重新启用一次重置提醒。这样可以覆盖电脑休眠越过旧窗口后的真实恢复，同时避免新窗口重新锚定或滚动调整时间造成连续误报。

首条新鲜观测只建立基线，不生成重置通知。应用休眠或退出后，只要本机仍保存旧基线，下一次新鲜刷新可以补判已经发生的换窗。

同一轮同时识别到 5 小时和周额度重置时，只投递周额度提醒；5 小时事件仍在去重账本中记为已处理，避免下轮刷新补弹。

### 3.3 用户主动重置

当前接口不返回操作主体。V1.1 使用以下组合信号识别已知的用户主动重置：

```text
重置机会数量减少
+ 5 小时额度显示 100%
+ 周额度显示 100%
```

命中后静默更新基线，不发送“周额度已重置”或“重置机会已生效”。重置机会数量必须来自与当前额度同一轮成功请求；旧缓存不能用于这项判断。

### 3.4 重置机会到期

- 每个有明确到期时间的可用机会，在剩余时间首次进入 24 小时时单独提醒。
- 多个机会同时进入提醒窗口时逐个投递，不合并。
- 多个机会到期时间完全相同时，通过“到期时间 + 同时间序号”分别去重。
- 已过期、没有到期时间、接口本轮未成功返回的数据不提醒。
- 应用在到期前 24 小时内首次启动时会补发；如果整个提醒窗口内应用均未运行，到期后不追发。

### 3.5 DeepSeek 与 Token

DeepSeek 余额仍采用 ¥5 触发、¥6 恢复的防抖区间。只有 Codex 或 Claude 当前识别为 DeepSeek 路由时才判断，两者共享余额只产生一个事件。

Token 按用户 Mac 当前时区的自然日累计。一次同步从 0.9 亿跳到 3.2 亿时只提醒最高的 3 亿档，并将较低档位一并记为已处理。文件变化以首条事件启动合并等待，后续连续写入不会反复顺延；扫描期间再次变化时保留一次补刷，正在执行的扫描不会被新事件取消。5 分钟轮询继续承担文件事件丢失和休眠恢复的兜底。

Codex 额度与 DeepSeek 余额在同轮都需要刷新时并行请求。额度、重置机会和余额提醒仍以约 60 秒的额度采样周期为基础，不存在 Token 文件事件的连续防抖链路。

## 4. 事件顺序、冷启动与去重账本

同一轮刷新按以下稳定顺序输出：

1. 5 小时额度；
2. 周额度；
3. 5 小时额度重置；
4. 周额度重置；
5. 按到期时间排列的各个重置机会；
6. DeepSeek 余额；
7. Token 里程碑。

每个事项生成独立通知或独立应用内卡片。同一轮的 5 小时与周额度重置会合并为一条周额度通知；余额或 Token 事件仍分别展示。

V5 账本按稳定规则 ID 保存规则状态；升级时从 V1、V2、V3 或 V4 转换：

- V1 已提醒过的额度窗口迁移为对应的 30% 档，升级后不会重复弹出；
- 同一窗口之后进入 5% 仍可再提醒；
- DeepSeek 低余额激活状态、Token 当日最高里程碑与周期键继续保留；
- 额度档位、周重置 occurrence、重置机会到期 occurrence 和上一条 Codex 观测转入各自规则状态；
- V4 增加 5 小时与周额度各自的重置提醒资格；V3 基线低于 100% 时启用，100% 或缺失时关闭；
- 重置 occurrence 使用刚结束或被替换的旧窗口时间，不再使用可能持续变化的新重置时间；
- 旧 V1～V4 键保留，供兼容与回滚读取。

Codex 路由离开官方模式时清除两类额度的重置观测基线；额度刷新失败时保留上一条有效基线，但不根据失败结果产生事件。

### 4.1 规则代码入口

`ReminderRuleCatalog` 是所有固定规则的唯一目录。每条 `ReminderRuleDefinition` 声明稳定 ID、数据源、新鲜度来源、条件、去重策略、顺序、跳转目标和文案模板。条件引擎支持多档额度阈值、带恢复边沿的额度窗口变化、到期时间窗、带恢复线的余额阈值和周期里程碑。额度 30% / 5% 共用阈值执行器；5 小时/周额度重置、主动重置压制、到期机会、DeepSeek 恢复线与 Token 里程碑使用同一个目录和事件投递路径，但保留各自必要的状态判断。

新增普通阈值规则时，只需登记目录定义、增加中英文文案并补边界测试；不需要添加事件枚举分支、Coordinator 文案分支或账本字段。新条件类型才需要扩展条件执行器，并覆盖触发、去重、数据新鲜度、重启和迁移测试。账本 V5 的状态以规则 ID 隔离；升级必须从旧账本迁移对应 occurrence、激活状态、里程碑、窗口基线、已提醒档位与重置提醒资格。投递层、8 秒应用内卡片、系统通知降级和点击跳转保持独立。

## 5. 文案

文案采用“标题说明当前变化，正文只提供必要时间”的结构。

| 类型 | 标题 | 正文 |
| --- | --- | --- |
| 5 小时额度 | Codex 5小时额度仅剩28% | 将于今天 16:30 重置 |
| 周额度 | Codex 周额度仅剩18% | 将于9月17日 23:07 重置 |
| 5 小时额度按时重置 | Codex 5小时额度已重置 | 5小时额度已恢复至100%，下次将于今天 21:30 重置 |
| 周额度按时重置 | Codex 周额度已重置 | 周额度已恢复至100%，下次将于9月24日 23:07 重置 |
| 周额度提前重置 | Codex 周额度已提前重置 | 周额度已恢复至100%，原定于9月17日 23:07 重置 |
| 重置机会到期 | 1个 Codex 重置机会即将到期 | 将于明天 18:00 到期 |
| DeepSeek | DeepSeek 余额提醒 | 余额仅剩 ¥4.20，请尽快续费 |
| Token | Token 用量提醒 | 今日累计已消耗 1.08亿 Token |

没有可靠额度重置时间时只显示低额度标题，不编造正文时间。英文界面提供含义一致的本地化文案。

## 6. 通知渠道与消失策略

| 当前状态 | 提醒方式 |
| --- | --- |
| 用户开启系统通知，且 macOS 已授权 | 使用 macOS 原生通知横幅并进入通知中心 |
| 系统通知关闭、未授权、被拒绝或投递失败 | 在菜单栏图标下方展示应用内提醒卡片 |

应用内卡片继续使用 QuotaMonitor 图标、现有圆角和边框：

- 每个事件一张卡片，同批事件纵向排列；
- 真实卡片默认 8 秒后自动消失；
- 鼠标停留暂停当前卡片倒计时；
- 点击正文关闭当前卡片并打开对应页面；
- Codex 新事件均进入“概览”，Token 进入“Token 看板”；
- 提醒不改变菜单栏图标，也不保留未读角标。

## 7. 设置与边界

设置页继续保留“额度与用量提醒”总开关和“系统通知”开关。关闭总开关时停止规则判断，并关闭当前应用内提醒。

V1.1 不覆盖：

- 用户自定义阈值、分项开关和静默时段；
- 5 小时或周额度到 0% 的额外提醒；
- 额度未按时恢复和数据源中断；
- 应用内提醒历史、逐条已读或稍后提醒；
- 自动使用重置机会；
- Claude 官方额度提醒；
- 邮件、短信、Webhook 或移动端推送。

## 8. 验收清单

### 8.1 规则

- 31% 不提醒，30% 提醒；同窗口到 5% 再提醒一次。
- 冷启动直接得到 4% 时只提醒“仅剩4%”，不补发 30%。
- 5 小时和周额度分别去重，确认补充额度后重新具备触发资格。
- 同窗口重置时间漂移 1 秒时，30% → 29% 不重复提醒。
- 5 小时额度按时换窗并显示 100% 时提醒。
- 5 小时额度在休眠期间越过旧重置时间，唤醒后只提醒一次。
- 额度保持 100% 时，服务端连续后移下一次重置时间不提醒。
- 重置提醒后持久化并重启，仍不补弹同一轮事件。
- 5 小时和周额度同时重置时，只提醒周额度。
- 周额度按时换窗并显示 100% 时提醒。
- 周额度提前换窗并显示 100% 时使用“已提前重置”文案。
- 周额度 `100% → 100%` 只更新基线，不生成重置提醒。
- 周额度显示 99% 时不产生重置事件。
- 首条观测、失败刷新和旧重置机会缓存不产生重置事件。
- 重置机会数量减少且两项额度均为 100% 时静默。
- 每个机会进入最后 24 小时单独提醒；相同到期时间仍逐个投递。
- V1 账本迁移后 30% 不重复，5% 仍可提醒。
- DeepSeek 和 Token 原有规则保持通过。

### 8.2 渠道与视觉

1. 关闭系统通知，检查应用内卡片的新版标题、正文、位置、关闭、悬停和 8 秒消失。
2. 开启系统通知并授权，检查原生横幅、通知中心留存和点击进入概览。
3. 同轮多事件逐条投递，应用内卡片纵向排列。
4. 覆盖浅色、深色、菜单栏靠近屏幕边缘和至少一种多屏布局。
5. README 截图必须来自真实运行应用，不能用静态检查代替视觉验收。
