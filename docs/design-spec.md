# QuotaMonitor 设计规范

版本：v3

状态：已确认，作为后续 UI 与展示逻辑改造的唯一设计依据

本规范记录 QuotaMonitor 当前实现采用的视觉与交互规则。

## 0. 文档目的

QuotaMonitor 是一个菜单栏优先的本地用量监控工具。用户通常只需要快速判断“今天用了多少、额度是否还能用”，在需要追溯时才打开主面板查看趋势和明细。

本规范同时约束：

- 信息架构与模块层级
- 平台、模型、路由、额度的业务语义
- 颜色、排版、间距、状态和交互
- 下拉框与主面板之间的数据一致性
- SwiftUI 组件拆分和验收口径

设计稿负责表达最终视觉与交互方向；真实数据、系统状态和本规范负责约束实现，不能用演示数据掩盖缺失状态。

## 1. 设计原则

### 1.1 先判断，再深入

下拉框承担快速判断，主面板承担分析与管理。用户打开下拉框后，应在几秒内看见今日总量、变化趋势、平台用量和额度状态。

### 1.2 每个数字都要能解释

每个数值必须明确对应一个时间范围、统计维度和分母。涉及“今日”“近 7 日”“累计”的内容，标题和计算口径必须一致。

### 1.3 状态要区分连接和数据可用

“本地数据源已连接”“官方额度已读取”“额度未读取”“服务未连接”是四种不同状态，不能统一显示为“正常”。

### 1.4 视觉服务于扫描

优先使用字号、间距、分组和对齐建立层级。装饰性进度线、无明确含义的颜色、重复解释性小字都不进入最终实现。

### 1.5 保留原生桌面感

主面板保留 macOS 窗口行为、菜单栏入口、原生交通灯和键盘操作。视觉稿中的窗口背景、阴影和卡片用于强化层级，不能替代真实窗口行为。

## 2. 信息和数据语义

### 2.1 四个独立维度

| 维度 | 定义 | 示例 | 使用位置 |
|---|---|---|---|
| 平台 | 用户通过哪个工具发起使用 | Codex、Claude、Claude Code、WorkBuddy | 平台用量、下拉框今日用量 |
| 客户端 | 平台的具体运行入口 | CLI、桌面端、插件 | 平台明细和排查 |
| 模型 | 实际调用的模型 | GPT、DeepSeek、Claude 模型 | 模型用量、模型类型趋势 |
| 路由/提供方 | 请求最终由谁提供服务 | 官方、DeepSeek | 额度卡、菜单栏角标、路由 pill |

平台、模型和提供方不能互相替代。例如：Codex 平台可以通过 DeepSeek 路由调用 DeepSeek 模型；这仍然是一条 Codex 平台用量。

### 2.2 时间范围

| 标签 | 分母/范围 | 适用位置 |
|---|---|---|
| 今日 | 本地自然日 00:00 至当前时间 | 下拉框今日用量、概览主指标 |
| 昨日 | 前一个本地自然日 | 今日对比 |
| 近 7 日 | 包含今天的连续 7 个自然日 | 概览、默认 Token 看板 |
| 近 30 日/90 日 | 对应连续自然日 | 有足够历史时启用 |
| 累计 | 当前可用的完整历史 | 明确显示历史起止范围 |

“平台用量 · 今日”的百分比必须以今日平台总量为分母；“模型用量 · 近 7 日”的百分比必须以近 7 日模型总量为分母。

### 2.3 展示状态

```text
loading       正在读取数据，保留布局并显示占位
ready         数据已成功读取
connectedOnly 数据源已连接，但额度字段尚未读取
unavailable   服务或账号未连接
empty         当前范围没有数据
stale         本次刷新失败，继续保留上次成功数据并提示更新时间
error         没有可用旧数据，显示错误和重试入口
```

状态显示优先级：错误/过期 > 未连接 > 已连接但额度未读取 > 已读取且正常。

## 3. 视觉系统

视觉基准以当前深色稿为主；现有浅色模式继续保留，所有 token 必须提供浅色和深色映射。深色模式先完成视觉验收，浅色模式随后按同一语义 token 验收。

### 3.1 颜色 token

| Token | 深色基准 | 用途 |
|---|---|---|
| `background` | `#0E1013` | 窗口底色 |
| `surface` | `#16181D` | 卡片、主内容面 |
| `surface2` | `#1C2026` | 标题栏、控件底 |
| `surface3` | `#242932` | 分段控件选中态、轨道 |
| `border` | `#272C35` | 普通描边、分隔线 |
| `borderStrong` | `#363D48` | 窗口和弹层强调描边 |
| `text` | `#F0F1F4` | 主文字 |
| `text2` | `#A3AAB5` | 次级文字 |
| `text3` | `#7B8593` | 辅助文字、占位、轴标签 |
| `codex` | `#6C82A3` | Codex、平台主数据、选中态 |
| `claude` | `#B88972` | Claude 平台 |
| `claudeCode` | `#8C7BA3` | Claude Code 平台 |
| `deepseek` | `#6F98A0` | DeepSeek 路由 |
| `workbuddy` | `#78A18F` | WorkBuddy 平台 |
| `modelFallback` | `#AAA59B` | 其他模型、合并项 |

平台和模型共用以上五个分类色。单张图表内优先不重复使用颜色；平台类别超过五类时才合并尾部平台。模型趋势图始终保留当前范围内的每个模型，模型排行卡仍可合并“其他模型”。
| `ok` | `#69BD93` | 正常、下降、同步成功 |
| `warn` | `#DCA869` | 未读取、低余额、提醒 |
| `danger` | `#E07C6C` | 上升、危急、退出/错误 |

颜色只承担稳定语义。红绿变化必须同时有箭头和文字，不依赖颜色单独传递信息。

### 3.2 字体与数字

- 字体栈：`-apple-system, SF Pro Text, PingFang SC, Noto Sans SC, system-ui, sans-serif`
- 所有 Token、金额、百分比、时间使用等宽数字
- 主标题 21–22px，卡片标题 12.5–13px，正文 11.5–12.5px，辅助信息 9.5–10.5px
- 文字对比度：正文至少 4.5:1，大字号至少 3:1
- 不用 monospace 装饰普通标题，只用于测量值、代码和模型名

### 3.3 形状与间距

- 卡片圆角 12px
- 控件圆角 8–11px
- 状态标签使用紧凑胶囊或小圆角矩形
- 主内容内边距 20–22px
- 卡片内边距 14–16px
- 主区块间距 12–16px
- 阴影用于窗口和下拉框层级；不使用零位移彩色光晕

## 4. 布局与模块规范

### 4.1 菜单栏

菜单栏是首要入口，显示 QuotaMonitor 通用标识和今日总量。平台/路由的细节进入下拉框，不把 Codex 图标误当成全局汇总图标。

交互：

- 左键和右键均打开下拉框
- 点击外部关闭
- 下拉框显示后不强制打开主面板
- 状态项宽度随内容变化，但不能跳动过大

### 4.2 下拉框

结构顺序：

1. 标题与更新时间
2. 今日总 Token
3. 较昨日变化标签
4. 额度状态
5. 今日平台用量
6. 近 7 日模型用量
7. 打开主面板、刷新、设置、退出

规则：

- 变化标签只包裹实际文字，不撑满整行
- 额度未读取显示“已连接 · 额度未读取”，未连接显示“未连接”
- Top 3 模型后追加“其他”，除非剩余为 0
- 今日平台百分比使用今日总量做分母
- 没有数据时显示 `—` 和明确状态，不显示空白字符串

### 4.3 主面板窗口

- 默认尺寸约 980×620，最小尺寸不低于 820×540
- 标题栏保留交通灯、窗口标题和数据源更新时间
- 左侧导航固定，数据源状态固定在底部
- 主内容可滚动，内容超出窗口时保留可见滚动反馈
- 侧栏顶部不放无意义占位高度

### 4.4 概览页

内容顺序：

1. `概览` 标题
2. 今日 Token 主指标
3. 较昨日标签
4. 近 7 日累计、今日峰值占比、用量领先模型
5. Codex / Claude 额度卡
6. 近 7 日趋势
7. 平台用量和模型用量

已确定的简化规则：

- 标题下方不放页面解释性副标题
- 统计值下面不放“7 天总量”“占周期总量”等重复小字
- 删除没有明确语义的黄色进度线
- 较昨日标签只表达变化，不伪装成进度条
- “正常”仅用于额度数据已成功读取且状态可判断的情况

### 4.5 Token 看板

指标条：总用量、有效日均、峰值、最高平台、最高模型。

趋势图：

- 支持“按平台 / 按模型”切换
- 图表分段按当前时间范围内真实出现的类别聚合
- 模型图例按当前区间动态展示，最多显示主要 6 个模型，其余合并为“其他模型”
- 7 日、30 日、90 日和累计切换时，柱体与图例同步重新计算
- 图例居中
- 平台用量卡单独表达客户端/工具维度
- 模型用量卡表达模型明细维度
- 不通过固定比例伪造平台或模型分布
- 柱状图不显示常驻柱顶数值，避免标签与网格、柱体争夺注意力
- 悬停按完整日期槽位触发：当前列提亮、其他柱体降权，完整明细通过提示卡查看
- 横轴线与日期标签保持紧凑间距，标签仍需完整可读且不贴住轴线
- 提示卡跟随当前柱体，与柱顶对齐并保留 8px 间距；优先显示在右侧，空间不足时切换到左侧
- 每根柱子采用同一套提示卡定位规则，切换 hover 对象时保持稳定的空间关系
- 提示卡内的分段明细按用量降序排列
- 堆叠分段之间使用细分隔线，避免小占比被相邻大分段吞没

热力图：

- 365 个自然日按周一至周日排列
- 单元格填满可用宽度
- 显示月份刻度
- 没有数据的日期显示为空态色，不与真实 0 用量混淆
- 数据不足时显示已记录天数

时间范围：

- 只有真实历史覆盖的范围可切换
- 数据不足的 30 日、90 日、累计按钮禁用或显示空态
- 平均值明确是“有效日均”还是“包含空日期的日均”，两者不能混用

### 4.6 设置页

- 页面只保留“设置”标题
- 单一设置卡不再显示“通用”分组标题
- 保留开机启动和语言设置
- 行内说明只解释具体开关，不添加页面级副标题
- 设置变化即时生效并保留系统原生控件语义

## 5. 组件与交互状态

核心组件：

- `PanelCard`
- `PageHeader`
- `StatusBadge`
- `QuotaCard`
- `MetricStrip`
- `TokenChart`
- `ChartLegend`
- `TokenHeatmap`
- `RankingCard`
- `EmptyState`
- `ErrorBanner`

每个数据型组件都需要支持：

- 正常数据
- 无数据
- 加载中
- 未连接
- 已连接但字段缺失
- 刷新失败且保留旧数据

交互要求：

- 所有按钮有明确的动作名和焦点态
- 交通灯按钮行为与原生窗口一致
- 时间范围按钮在数据不足时不可点击
- 图表不把颜色作为唯一信息来源
- 菜单栏和主面板使用同一份展示快照

## 6. 数据映射原则

展示层不得直接在 View 中重复拼装业务口径。建议由 Store 输出统一快照：

```text
QuotaStore
  ├─ QuotaPresentationSnapshot
  │   ├─ syncState
  │   ├─ routeSummary
  │   ├─ quotaCards
  │   ├─ todayUsage
  │   ├─ yesterdayUsage
  │   ├─ platformBreakdown
  │   ├─ modelBreakdown
  │   └─ historyAvailability
  ├─ DropdownSnapshot
  └─ TokenDashboardSnapshot
```

来源映射：

- 官方 Codex 额度：`ProviderUsage.weekly/session`
- DeepSeek 共享余额：`QuotaStore.deepSeekBalance/deepSeekDays`
- 今日/昨日 Token：`QuotaStore.todayTokenUsage/yesterdayTokenUsage`
- 平台聚合：`TokenUsageBucket.platform`
- 客户端聚合：`TokenUsageBucket.client`
- 模型聚合：`TokenUsageBucket.model`
- 路由聚合：`TokenUsageBucket.provider`
- 历史可用范围：`QuotaStore.totalTokenHistory` 的最早和最晚日期

## 7. 验收标准

### 视觉

- [ ] 深色模式与改造版视觉稿保持一致
- [ ] 浅色模式使用同一套语义 token，没有旧色残留
- [ ] 标题、副标题、统计小字符合最终简化规则
- [ ] 标签只包裹文字
- [ ] 图例居中
- [ ] 热力图铺满宽度并显示月份刻度
- [ ] 数据源状态固定在侧栏底部

### 数据

- [ ] 今日平台占比以今日总量为分母
- [ ] 近 7 日模型占比以近 7 日模型总量为分母
- [ ] 平台、模型、路由互不混淆
- [ ] 额度未读取不会显示为正常
- [ ] Top N 后能看到其他汇总
- [ ] 历史不足不会用假数据填充成可用状态

### 状态与交互

- [ ] 官方+官方、官方+DeepSeek、DeepSeek+官方、双 DeepSeek 四种路由组合可用
- [ ] 未连接、加载中、错误、空数据、过期数据均有明确表现
- [ ] 下拉框点击外部可关闭
- [ ] 主面板可滚动，滚动反馈可见
- [ ] 交通灯、菜单栏动作和设置动作可操作
- [ ] 中英文文案不溢出

## 8. 禁止事项

- 不在 View 中自行决定百分比分母
- 不用固定比例模拟平台或模型分布
- 不把“连接正常”当作“额度已读取”
- 不用空字符串隐藏错误状态
- 不为每个页面继续添加解释性副标题
- 不再维护两套并行的主面板实现
