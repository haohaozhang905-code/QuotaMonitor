> 状态：Active<br>

> 最近更新：2026-09-21<br>

## 1. 文档定位

本文定义 QuotaMonitor 的项目级视觉、交互和界面状态规范，供产品、设计、研发、测试和编程 Agent 共同使用。

- 功能 `spec.md` 决定用户问题、行为和验收结果；
- 本文决定这些行为如何以一致、可访问、可复用的界面呈现；
- `plan.md` 决定组件、数据流和实现步骤；
- [`PanelTheme.swift`](../Sources/QuotaMonitor/Views/PanelTheme.swift) 承载设计 Token 的代码实现；
- 功能验收记录说明自动化、真实应用和视觉检查是否完成。

本文是当前设计基线，不证明历史版本在编码前已经建立了完整规范。未来修改公共 Token、信息层级或核心组件时，应先更新本文或建立设计 ADR，再修改代码。

### 1.1 历史来源与合并结论

仓库曾包含 [`docs/design-spec.md` v4](https://github.com/haohaozhang905-code/QuotaMonitor/blob/d416fb9bc288239b42ed899ca07b1339eb9d6f1b/docs/design-spec.md) 和配套的 [`implementation-plan.md` v1](https://github.com/haohaozhang905-code/QuotaMonitor/blob/d416fb9bc288239b42ed899ca07b1339eb9d6f1b/docs/implementation-plan.md)，随后在提交 [`0b24094`](https://github.com/haohaozhang905-code/QuotaMonitor/commit/0b24094) 中随旧 UI 清理删除。v4 仍是重要的设计决策来源，但其中部分数值和页面结构已经被后续实现替代。

本版采用以下合并方式：

| 历史 v4 内容 | 当前处理 | 原因 |
| --- | --- | --- |
| 菜单栏优先、先判断再深入 | 保留 | 仍符合当前产品定位与信息架构 |
| 平台/客户端/模型/路由四维语义 | 保留并恢复到本文 | 当前数据模型仍明确保存这些维度 |
| 今日/近 7 日/累计的时间与分母 | 保留并扩展 | 防止跨页面统计口径漂移 |
| 加载、可用、仅连接、过期、错误等状态 | 保留并对齐当前枚举 | 当前展示快照与来源诊断仍依赖这些状态 |
| 标准 macOS 窗口、智能 Dock、尺寸记忆 | 保留 | 当前 `MainPanelController` 仍实现这些行为 |
| 旧深色蓝灰色板 | 更新为当前 Steep 双主题色板 | 当前 `PanelTheme` 已完成语义迁移 |
| 卡片圆角 12 pt | 更新为当前主卡 24 pt | 现行界面和公共 `panelCard` 已改变 |
| 普通标题不使用等宽字体 | 更新为当前页面标题使用等宽设计 | 当前概览、Token 和设置标题均采用等宽样式 |
| 图表类别尽量不重复、超限合并 | 更新为稳定 ID 映射，图表保留全部类别并稳定复用五色 | 排序变化时保持颜色身份比一次性不重复更重要 |
| 数据源状态固定在侧栏底部 | 退役，改由设置页集中诊断 | 当前侧栏只承担三项主导航 |
| 主面板滚动条必须可见 | 退役，保留滚动能力并隐藏系统指示器 | 当前内容通过卡片边界和留白表达滚动区域 |
| 深色先验收、浅色随后补验 | 更新为浅色/深色同级验收 | 当前产品同时正式支持两种外观 |
| 提醒卡、键盘图表、VoiceOver、证据等级 | 本版新增 | 历史 v4 尚未覆盖后续能力 |

出现冲突时，以当前功能 Spec、本文当前版本和代码中的语义实现为准；历史 v4 用于解释设计演进，不直接作为现行数值来源。

### 1.2 透明模糊范围（2026-09-21 v1.7 修订）

透明模糊只用于下拉框和主面板侧栏。主面板右侧顶部横条属于正文列，使用与正文一致的实色背景并承担窗口拖拽；开启“减少透明度”时，保留的模糊区域也回退为实色。

| 区域 | 表面 | 说明 |
| --- | --- | --- |
| 下拉框 | 系统 `popover` 材质 | 从窗口后取样并保持 active，不叠加固定纸色蒙层；主文字与次级文字使用独立高对比 token，品牌图标保持原彩色；降低透明度时使用 `surfaceFloat` |
| 侧栏 | 系统 `sidebar` 材质 | 使用 `behindWindow` 从桌面取样，不叠加固定主题色；深色外观下品牌文字、导航文字和图标统一为纯白；选中项保持 `sidebarSelected` 实色 |
| 右侧顶部横条 | `background` 实色 | 与右侧正文画布保持一致，保留底部分隔线；整条横条支持按住拖拽窗口，双击保持窗口缩放行为 |
| 内容画布、卡片、分段控件、开关、tooltip、提醒卡 | 既有实色表面 | 保持数字与控件的稳定对比度 |

- 不固定高斯模糊半径，由系统材质控制模糊强度。
- 深色下拉框的主文字使用近白色，次级文字使用清晰中灰；品牌图标维持产品原有彩色，不由下拉框统一改色。
- 材质承担背景模糊、透明度和桌面颜色适配；除强调状态外，不用固定深浅色蒙层补偿前景对比度。
- 验收需在浅色、深色、复杂桌面及“减少透明度”下检查侧栏和下拉框；同时检查右侧顶部与正文同色、拖拽窗口可用，其他表面维持实色。

## 2. 适用范围

覆盖以下产品表面：

1. macOS 菜单栏状态；
2. 360 pt 下拉框；
3. 主面板的概览、Token 看板和设置页；
4. 图表、提示浮层、状态卡和空数据/错误状态；
5. 系统通知与应用内提醒卡片；
6. 浅色、深色、中英文、键盘和辅助功能状态。

平台品牌素材的官方颜色可以保留自身识别度，但页面背景、文字、状态、图表分类和组件层级必须使用公共语义 Token。

## 3. 体验原则

### 3.1 先回答当前最重要的问题

- 菜单栏和下拉框用于快速判断，不堆叠完整分析；
- 概览首屏优先显示风险、今日 Token 和额度状态；
- Token 看板再展开趋势、平台/模型分布和历史热力图；
- 设置页始终可达，数据失败时仍可用于恢复和诊断。

### 3.2 每个数字都能解释

每个数字必须对应明确的事实来源、时间范围、统计维度、单位和分母。下拉框、概览和 Token 看板展示同一事实时，应消费同一展示快照与格式化规则，不能在各页面重新计算出不同结果。

### 3.3 数据状态必须可解释

界面需要区分加载、可用、部分可用、过期、无数据、权限不足、格式不支持和请求失败。不得把缺失或失败展示为 `0`，也不得只靠颜色表达状态。

### 3.4 克制的原生感

- 使用 macOS 系统字体、SF Symbols、系统按钮与开关行为；
- 卡片依靠表面色差、细描边和有限投影形成层级；
- 页面内不使用大面积高饱和渐变或与数据无关的装饰；
- 动效帮助理解状态变化，不能造成状态被修改的错觉。

### 3.5 同一事实只建立一套视觉语义

额度、余额、Token 和数据源状态在不同页面使用相同的名称、格式和状态色。图表分类色根据稳定的平台或模型 ID 映射，不能随着列表排序改变。

## 4. 信息架构

### 4.1 四个独立业务维度

| 维度 | 定义 | 示例 | 主要使用位置 |
| --- | --- | --- | --- |
| 平台 | 用户通过哪个工具发起使用 | Codex、Claude、WorkBuddy | 平台用量、下拉框今日用量 |
| 客户端 | 平台的具体运行入口 | CLI、桌面端、插件 | 来源诊断、平台细分 |
| 模型 | 实际调用的模型 | GPT、Claude、DeepSeek 模型 | 模型趋势和排行 |
| 路由/提供方 | 请求最终由谁提供服务 | 官方、DeepSeek | 额度、余额和路由状态 |

四个维度不能互相替代。例如，用户从 Codex 发起、经 DeepSeek 路由调用 DeepSeek 模型，这条记录的平台仍是 Codex，提供方和模型才是 DeepSeek。界面文案、图表切换和后端字段都应保留这一边界。

### 4.2 时间范围与分母

| 标签 | 计算范围 | 约束 |
| --- | --- | --- |
| 今日 | 用户 Mac 当前时区 00:00 至当前时间 | 下拉框和概览主指标使用同一数值 |
| 昨日 | 前一个本地自然日 | 仅作为今日比较基线 |
| 近 7 日 | 包含今天的连续 7 个自然日 | 默认趋势与概览摘要 |
| 近 30 日/90 日 | 对应连续自然日 | 历史不足时禁用或说明，不补造零数据 |
| 累计 | 当前可读取的完整历史 | 明确历史覆盖范围，不宣称账号全量 |

“平台用量 · 今日”的占比以今日平台总量为分母；某时间范围的模型占比以相同范围的模型总量为分母。有效日均与包含空日期的自然日均必须明确区分。

### 4.3 界面状态模型

| 状态 | 用户看到的含义 | 设计要求 |
| --- | --- | --- |
| `loading` / `scanning` | 正在读取或扫描 | 保留稳定布局，显示进度或占位 |
| `ready` | 数据已成功读取 | 展示事实、单位与更新时间 |
| `connectedOnly` | 已识别服务，但额度字段不可用 | 明确写出“已连接/额度未读取” |
| `empty` / `noData` | 当前范围没有有效记录 | 解释原因，不用空白或伪造的 0 |
| `unavailable` / `notDetected` | 服务或来源未连接/未识别 | 提供配置或诊断入口 |
| `needsPermission` | 系统权限阻止读取 | 指明所需权限与恢复动作 |
| `unsupportedFormat` | 来源存在但格式尚不支持 | 不误报为正常或无用量 |
| `stale` | 本次刷新失败，仍有上次成功数据 | 保留旧值并显式标记更新时间 |
| `error` / `failed` | 没有可用结果 | 显示错误与重试入口 |

呈现优先级遵循：明确错误或过期 > 权限/格式问题 > 未连接 > 已连接但字段缺失 > 已读取。状态不能只靠一个彩色圆点表达。

### 4.4 产品表面分工

| 层级 | 核心任务 | 主要内容 | 不承担 |
| --- | --- | --- | --- |
| 菜单栏 | 无需打开窗口即可感知关键状态 | 图标、简短额度或用量 | 诊断与长说明 |
| 下拉框 | 10 秒内完成快速判断与跳转 | 今日 Token、关键额度、更新时间、快捷操作 | 完整趋势分析 |
| 概览 | 判断当前风险及近期状态 | 风险卡、今日用量、额度/余额、短趋势 | 全量明细 |
| Token 看板 | 分析变化和分布 | 周期、趋势、排行、热力图、提示浮层 | 额度换算 |
| 设置 | 配置并排查数据来源 | 启动、语言、外观、提醒、来源状态 | 隐藏数据失败 |
| 提醒 | 在离开主界面时提示关键变化 | 标题、事实、入口、关闭/自动消失 | 自动兑换、充值或修改路由 |

## 5. 颜色系统

所有公共界面颜色从 `PanelTheme` 引用。禁止在业务视图中为同一语义重复定义十六进制颜色。

### 5.1 基础语义 Token

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `bg` / `background` | `#FFFFFF` | `#111215` | 窗口与画布背景 |
| `ink` / `text` | `#17191C` | `#CFCBC2` | 主文字、主要数据 |
| `paper` / `surfaceFloat` | `#FFFFFF` | `#17181C` | 浮动卡、下拉框、提醒卡 |
| `mist` / `surface` | `#F2F2F3` | `#1B1C20` | 静态卡、侧栏分区 |
| `fog` | `#FAFAFB` | `#131417` | 交替分区背景 |
| `slate` / `text2` | `#777B86` | `#A29F98` | 次级文字、辅助信息 |
| `ash` / `text3` | `#979799` | `#7C7A75` | 三级标签、坐标轴 |
| `hairline` / `border` | `#ECECEC` | 白色 8% | 卡片描边与轻分隔 |

`surface2` 用于轨道、关闭态和内嵌槽；`tooltipSurface` 与 `tooltipBorder` 只用于悬浮提示，深色模式下比普通卡片提亮一级。

### 5.2 状态色

| 语义 | 文字/图标 | 柔和背景 | 使用要求 |
| --- | --- | --- | --- |
| 正常 | `ok` | `okSoft` | 同时提供图标或文字结论 |
| 关注 | `warn` | `warnSoft` | 表示需要留意、过期或部分可用 |
| 危急 | `danger` | `dangerSoft` | 表示额度耗尽、明确失败或需要处理 |
| 未知/加载 | `text2` 或 `codex` | `surface2` | 不套用正常绿色，不显示为零 |

同一个状态组件至少同时提供“颜色 + 文本”或“颜色 + 图标 + 辅助功能标签”。正文和关键数字需保持可读对比度；最终以浅色、深色真实界面检查为准。

额度状态只按界面显示的整数百分比分档，并与提醒阈值共用 `QuotaRiskPolicy`：

| 显示剩余额度 | 状态 | 数字与图标 |
| --- | --- | --- |
| 31%～100% | 正常 | 关键数字使用主文字色；状态标签可使用 `ok` |
| 6%～30% | 需关注 | 使用 `warn`，对应 30% 提醒档 |
| 0%～5% | 高风险 | 使用 `danger`，对应 5% 提醒档 |
| 未读取 | 未知 | 使用 `text2`，不得显示为 0% |

5 小时额度和周额度使用完全相同的分档。重置时间只显示事实，不参与颜色或风险等级计算。菜单栏继续使用 macOS 模板单色；系统通知由 macOS 控制外观，标题需要明确写出“需关注”或“高风险”。应用内 30% 提醒使用 `warn` 强调，5% 提醒使用 `danger` 强调。

### 5.3 品牌与图表颜色

- 品牌色只用于品牌识别和与品牌直接相关的数据：`codex`、`claude`、`claudeCode`、`deepseek`、`workbuddy`；
- 图表使用 `chartPrimary`、`chartAccent`、`chartNeutral`、`chartDim`、`chartSand` 五色；
- 平台/模型颜色必须由稳定 ID 映射，同一对象跨页面保持一致，类别超过五个时稳定复用；
- 热力图使用 `heat0` 至 `heat4` 表示强度，不能引入另一套临时渐变；
- 图例、提示浮层和辅助功能摘要必须能在没有颜色的情况下解释数据。

## 6. 字体与数字

优先使用系统字体。数字、时间、平台/模型名、坐标轴和短标签使用等宽设计，中文品牌标题可使用 PingFang SC。

| 层级 | 建议规格 | 当前典型用途 |
| --- | --- | --- |
| Hero 数字 | 34 pt，Semibold/Bold，等宽 | 今日 Token 核心数字 |
| 页面标题 | 22 pt，Bold，等宽 | 概览、Token、设置标题 |
| 关键状态 | 15 pt，Semibold | 风险卡结论 |
| 卡片标题 | 12–14 pt，Semibold | 下拉框、来源、提醒标题 |
| 正文 | 11–12.5 pt，Regular | 说明、提醒详情 |
| 标签/坐标 | 9–11 pt，Medium/Regular，等宽 | 单位、时间、图例、辅助信息 |

规则：

- 同一数据在各页面沿用统一格式化函数，不手写单位、百分号或日期格式；
- 长数字使用本地化缩写与千位逻辑，不能单纯缩小字号来塞入；
- 中文和英文都需检查截断；标题最多一至两行，表格原因最多两行；
- 关键事实的字号与颜色层级高于解释文字。

## 7. 间距、尺寸与层级

以 4 pt 为基础节奏，优先使用 4、8、12、16、20、24 的间距。已有组件因像素对齐使用 3、5、7、10、14、15、18、22 时可以保留，新增组件先复用现有层级。

| 对象 | 当前基线 |
| --- | --- |
| 主面板最小尺寸 | `820 × 540 pt` |
| 主面板侧栏宽度 | `210 pt` |
| 页面内容边距 | 水平 `22 pt`，顶部 `18 pt`，底部 `24 pt` |
| 页面区块间距 | `14 pt` |
| 标准卡片内边距 | 水平 `16 pt`，上下通常 `16 pt` |
| 标准卡片圆角 | `24 pt` |
| 下拉框 | 宽 `360 pt`，水平内边距 `12 pt`，圆角 `20 pt` |
| 应用内提醒卡 | 内容宽 `372 pt`，内边距 `15 pt`，圆角 `14 pt` |
| 分段控件 | 单项 `60 × 26 pt`，外部 `2 pt` 内边距 |
| 图表提示浮层 | 宽 `140–350 pt`，圆角 `20 pt` |

普通静态卡使用 `surface`，不加投影；可浮起或可交互的卡使用 `surfaceFloat + border`，仅在需要表达悬浮层级时使用小投影。不要同时叠加强描边、深阴影和明显色差。

## 8. 核心组件规范

### 8.1 导航与操作

- 菜单栏是首要入口，左右键均打开或关闭下拉框；点击外部关闭，下拉框不会自行强制打开主面板；
- 状态栏使用系统高亮容器，不另绘与 macOS 冲突的点击背景；加载状态和真实额度状态应具有不同的可访问名称；
- 下拉框按“标题/更新时间 → 今日 Token/比较 → 数据状态 → 额度 → 今日平台 → 近 7 日模型 → 快捷操作”的扫描顺序组织；
- 下拉框先关闭再进入主面板或设置，避免两个浮层同时争夺焦点；
- 主面板使用标准 `NSWindow`，默认约 `980 × 620 pt`、最小 `820 × 540 pt`，支持缩放、最小化、Mission Control、尺寸位置记忆和原生交通灯；
- Dock 图标保持“智能 / 始终 / 从不”三种模式；智能模式下窗口打开或最小化时可从 Dock 找回，关闭主窗口后菜单栏继续运行；
- 侧栏当前项使用选中表面、文字权重和图标共同表达；悬停态弱于选中态；
- 下拉框快捷操作保持 `⌘O`、`⌘R`、`⌘,`、`⌘Q`，危险操作使用 `danger`；
- 可点击卡片需要完整点击区域和明确辅助功能名称；纯展示卡片不得伪装成按钮；
- 设置页使用原生开关。进入页面时不播放可能让用户误以为设置被改变的补间动画。

### 8.2 状态卡与空状态

- 风险卡每次只给一个最高优先级结论，并说明来源与更新时间；
- 加载时说明正在读取；旧缓存明确标“过期/沿用”；失败时给恢复入口；
- 数据源诊断分别说明额度与 Token 能力，不能用一个总状态掩盖部分失败；
- 空状态要区分“未安装”“尚无记录”“权限不足”“格式不支持”和“请求失败”。

概览页按“页面标题 → 最高优先级风险 → 今日 Token 主指标 → 额度/余额 → 趋势与分布”组织。Token 看板按“标题/时间范围 → 指标条 → 趋势图 → 平台与模型排行 → 年度热力图”组织。页面标题下不重复放无行动价值的解释性副标题。

### 8.3 图表与提示浮层

- 图表必须有可读标题、时间范围、单位与图例；
- 悬停、方向键或辅助功能调整都能选择数据；回车/空格可固定，Esc 可清除；
- 提示浮层根据真实内容测量，宽度限制在 `140–350 pt`，并保持在容器可见区域；
- 短柱仍需拥有可命中的交互区域；排序变化不能改变类别颜色；
- 无数据时展示解释状态，不绘制容易被理解为真实 `0` 的图形。

### 8.4 提醒卡片

提醒体验遵循 [`QMR-001`](../specs/001-reminder-v1.1/spec.md) 的行为要求：

- 卡片包含应用图标、标题、事实详情、关闭操作和打开目标页的入口；
- 卡片默认 8 秒消失，悬停暂停，点击后关闭并导航；
- 多个事件独立堆叠且顺序稳定；
- 面板位置必须限制在当前屏幕 `visibleFrame` 内，多屏和菜单栏位置变化不能使其移出屏幕；
- 原生系统通知样式由 macOS 管理，应用内卡片使用相同标题与事实语义；
- 提醒卡的真实浅色、深色、单条、多条、点击、悬停和自动消失结果记录在 [`acceptance.md`](../specs/001-reminder-v1.1/acceptance.md)。

## 9. 动效与反馈

- 页面切换使用约 `0.16s easeOut` 的轻量淡入/位移；
- 分段控件选择约 `0.14s easeOut`；
- 系统“减少动态效果”开启时取消非必要动效；
- 加载、刷新和提醒消失应保留清楚的状态反馈；
- 动效不改变数据含义，不用无限脉冲表达普通静态状态。

## 10. 无障碍与本地化

- 图标如果只是装饰，应对辅助技术隐藏；状态图标需有可读标签；
- 图表必须可聚焦，并提供整体摘要与键盘选择；
- 交互组件提供 `accessibilityLabel`，必要时补充 `Value` 和 `Hint`；
- 不依赖 hover 才能获得完成任务所需的信息；
- 所有用户可见文案进入中英文资源，截图和验收同时覆盖两种语言的关键长文案；
- 使用系统“减少动态效果”设置；新增界面还需检查键盘路径和 VoiceOver 朗读顺序。

## 11. 展示模型与组件边界

界面层消费统一的只读展示状态，避免在 View 中重新决定业务口径：

```text
QuotaStore
  └─ QuotaPresentationSnapshot
      ├─ availability / updatedAt
      ├─ today / lastSevenDays
      ├─ platform breakdown
      ├─ model breakdown
      └─ history availability
          ├─ DropdownPresentation
          └─ TokenDashboard presentation
```

公共组件职责：

| 组件 | 主要职责 | 不能承担 |
| --- | --- | --- |
| `PanelTheme` | 颜色与层级 Token | 业务阈值和数据计算 |
| `panelCard` | 卡片表面、间距、圆角和浮起层级 | 页面独有数据语义 |
| `PanelSegmentedControl` | 时间范围和图表维度的统一选择交互 | 判断历史是否真实可用 |
| `StackedBarChart` / 热力图 | 展示统一快照、键盘选择和提示 | 伪造缺失日期或分布 |
| `DropdownPopoverView` | 快速摘要与导航 | 单独重算跨页面指标 |
| `ReminderToastView` | 提醒事实、打开与关闭交互 | 判断是否应该触发提醒 |

禁止事项：

- 不在 View 中自行决定百分比分母或数据新鲜度；
- 不用固定比例或演示数据模拟平台、模型和额度分布；
- 不把“连接正常”写成“额度已读取”；
- 不用空字符串隐藏错误、缺失或不支持状态；
- 不为同一公共组件维护多套无法追踪的实现；
- 不让下拉框、主面板和提醒分别拼装同一事实的不同文案或数值。

## 12. 设计变更流程

出现以下任一变化时，需要更新本文或建立 ADR：

- 新增/修改公共颜色、字号、间距、圆角、阴影或图表映射；
- 改变菜单栏、下拉框、主面板导航或信息优先级；
- 新增跨页面公共组件；
- 改变状态语义、空状态、错误和降级呈现；
- 引入新字体、图标体系或第三方设计系统。

实施顺序：

1. 在功能 Spec 中定义用户行为与视觉验收场景；
2. 确认复用的 Token、组件和例外；公共变化先更新本文；
3. 在 Plan 中列出组件、状态、响应尺寸、本地化和无障碍方案；
4. 实现时从 `PanelTheme` 与公共组件引用语义，不复制魔法值；
5. 完成静态检查、逻辑测试、真实 App 检查和视觉验收；
6. 在 `acceptance.md` 或 Pull Request 中记录证据与仍待确认项。

## 13. 设计验收清单

- [ ] 信息层级能够在 10 秒内回答该页面的核心问题；
- [ ] 正常、加载、空数据、失败、过期和部分可用均有定义；
- [ ] 使用公共语义 Token，品牌色与状态色没有混用；
- [ ] 同一平台/模型的图表颜色跨页面稳定；
- [ ] 平台、客户端、模型、路由没有混用；统计范围、单位和分母可解释；
- [ ] 下拉框、概览和 Token 看板的同一指标来自统一展示快照；
- [ ] 额度在 31%、30%、6%、5%、0% 和无数据边界下跨页面颜色一致，且不受重置时间影响；
- [ ] 官方、DeepSeek、混合路由、未连接和额度缺失组合均有明确状态；
- [ ] 默认窗口、最小窗口、菜单栏下拉框与主面板滚动路径已检查；
- [ ] 浅色与深色真实界面已检查；
- [ ] 中文与英文长文案、数字极值和窄窗口已检查；
- [ ] 键盘、VoiceOver 标签和减少动态效果已检查；
- [ ] 浮层、提示和提醒在屏幕或容器可见范围内；
- [ ] 截图已脱敏，并记录构建或提交来源；
- [ ] 明确区分代码存在、自动化通过、真实应用通过与视觉通过。

## 14. 当前证据边界

当前主题 Token、四维数据模型、统一展示快照、原生主窗口、主面板、下拉框、图表键盘交互与提醒卡均能在代码中找到对应实现，README 也保存了浅色/深色产品截图。本文属于历史 v4 与当前实现合并后的事后基线；它本身不能证明所有当前修改已经完成真实 App 视觉验收。

后续新增页面或生成可交付 HTML 时，应沿用本文的语义 Token、状态模型、组件层级和验收清单；企业后端字段、接口、错误码和权限契约应在对应功能的 Spec、Plan 或 API 合同中另行定义。
