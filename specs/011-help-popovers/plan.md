# 实施计划

## 方案

复用现有 PanelHelpButton 和系统 NSPopover，移除覆盖正文的 tooltipSurface。将公共组件独立到 PanelHelpButton.swift，通过公开 AppKit API 设置 animates=false，使用系统统一绘制正文/箭头/阴影。保持 transient 关闭机制，delegate 回写绑定；移除触发视图时清理 popover。无需第三方依赖，也不实现另一套箭头几何或动画系统。

原生锚点作为按钮背景，不参与命中测试；显式传递 SwiftUI 外观与语言环境。周期切换沿用缓存按钮的 id，页面移除时销毁协调器并关闭。按需创建内容 hosting controller，不为关闭状态建立说明视图。

真实键盘检查发现焦点不会自动触发普通 Button，显式处理 space / return / escape；关闭后保留原焦点；仅在弹框显示时添加限定所属窗口的 Escape 本地事件监听，兼容图表仍持有焦点的情况，关闭/销毁时移除监听。深色系统材质比主面板底色更亮，说明正文和重置说明改用系统 primary 前景色，保留原字号 / 字重层级，避免使用针对实色画布定义的灰色和棕色。

## 验证与风险

自动化覆盖无动画、关闭回写、移除清理与内容更新；运行全量 swift test、SDD 和安全门禁。候选 app 在临时目录组装，不替换安装版。真实窗口检查三处入口、点击/外部/Escape、切周期、浅深色、中英文与小窗；系统弹框位置由 AppKit 最终决定，需要实际检查屏幕边界。

## 回滚

恢复本次公共组件和调用位置的差异，保留此前缓存统计及其他未提交改动；无持久化迁移和缓存回滚。安装版不受本次构建影响。

## 复审实施计划（2026-11-09）

用户已授权三个扫描项及安装替换。系统 NSPopover 的材质、边框和阴影无法通过公开 API 分别可靠控制，复用仓库现有 borderless nonactivating NSPanel 模式展示说明；hasShadow=false，SwiftUI 单一 Shape 填充近白背景和箭头，不描边。限制到父窗口内容/屏幕可见范围，保持同步开关、外部点击、Escape、页面/周期/窗口切换清理，按需挂载事件监听。使用公开 API，不依赖第三方组件或系统私有外壳。

排行改为独立视图持有 hover 状态，父页在数据更新时对选中周期单次分组生成汇总；指标共用同一 total。补充真实语义测试覆盖模型归一、other、未知和过期排除。设置状态模型从 ready/不可用二分改为带原因的展示枚举，并按状态单独渲染原因颜色；新增状态语义双语资源。

验证：全量逻辑和原生窗口生命周期测试；汇总结果与旧逐行过滤算法固定样本对照，并记录批量汇总耗时；浅深色、双语、三处问号与静态辅助功能实际检查。候选通过后先 ditto 备份安装版到 .artifacts，退出当前进程，再把已签名候选复制到临时 incoming 路径校验并原子替换，保留旧包用于回滚。不改安装脚本、应用身份、登录项或源日志。

## 第二次用户审稿实施计划（2026-11-09）

在同一 HelpBubble Shape 上绘制低对比自定义阴影；AppKit 窗口自身仍无系统阴影/边框。围绕轮廓留出透明内边距并在锚定位置计算中扣除该内边距，避免阴影裁切或箭头脱离问号。保持浅/深色不同的克制透明度。

英文缓存说明压缩到更短句；重置卡弹框将编号与到期时间合并成紧凑单行并在极窄情况下轻微缩放；Token 看板英文指标缩短为一行标签，同时降低单元水平内边距并限制标签换行。中文文案内容保持原意。跑全量测试、文档门禁、双语 key parity，构建签名候选后检查真实中英文布局，完成后用已有授权替换安装版并记录哈希与回滚包。
