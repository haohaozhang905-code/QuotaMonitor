# Codex 同一会话多日志片段用量合并产品规范

## 1. 背景与用户问题

Codex 会将同一对话的活动记录写入多个 rollout 文件。当前本机发现同一 `session_id` 的多个文件分别记录了模型切换前后的用量；解析器按会话 ID 只保留较新的文件，导致较早片段中的模型用量消失。目标对话“修复安卓实况图导出报错”因此漏掉 `gpt-6.2-sol`。

## 2. 核心任务

用户查看 Codex 本机 Token 统计时，能同时看到同一对话各日志片段中真实记录的模型用量，且重复记录不会重复累计。

## 3. 目标

- 保留同一会话 ID 下各个不同 rollout 片段中的结构化用量。
- 按日志中的模型上下文将请求归到对应模型。
- 对片段重叠和普通 / 压缩副本做保守去重。
- 从本机仍存在的 JSONL 与 JSONL.ZST 源日志重建旧聚合缓存。

## 4. 非目标

- 不补算云端、网页端或其他设备上没有落在本机日志中的 Token。
- 不根据文本、上下文窗口或额度推算 Token。
- 不改变日期时区、Token 字段口径、平台 / 客户端分类或模型展示名称。
- 不改动状态栏、安装身份、提醒、网络请求和其他 Token 来源。

## 5. 需求

### ROLL-001：保留同一会话的不同日志片段

同一会话 ID 下以不同 rollout 身份存在的日志片段均参与解析；只有相同 rollout 的普通 / 压缩或归档副本才按副本规则择一读取。

### ROLL-002：跨片段按模型归属并去重

解析器按片段内模型上下文关联后续用量。片段之间确认重复的同一请求最多统计一次；有明确请求级用量时保留该用量，只有累计用量时按会话累计序列求增量。不得仅因两个事件累计值相同就去重。

### ROLL-003：缓存升级可重建

新缓存口径从本机可读源日志完整重算。重算成功后，同一日期、平台、客户端和模型桶与冷扫结果一致；扫描失败或有片段不可读时沿用 last-good，不以部分结果覆盖成功快照。

### ROLL-004：兼容 fork 与格式副本

父子 fork 仍只统计子会话新增请求；同一 rollout 的 `.jsonl` / `.jsonl.zst`、跨目录或改名副本仍最多统计一次。源日志保持只读。

## 6. 状态与异常场景

| 场景 | 用户体验 |
| --- | --- |
| 正常 | 同一对话多个日志片段的用量均出现在对应日期和模型下。 |
| 空数据 | 没有可解析的结构化用量时不补零或估算。 |
| 重复片段 | 可确认重合的请求只计一次；不能确认的冲突不静默删掉用量。 |
| 读取失败 | 整体 Codex 扫描失败并保留 last-good 结果，不发布不完整新汇总。 |
| 缓存重建 | 使用新聚合版本重扫本机源文件；不修改源文件，不保留旧错误模型桶作为额外用量。 |

## 7. 设计约束

不涉及用户界面。遵循 `docs/PRODUCT.md`、`docs/DATA_SOURCES.md` 和 `docs/ARCHITECTURE.md` 的本机只读、缺失不估算和 last-good 边界。缓存不得保存会话正文、认证信息或完整日志行。

## 8. 验收标准

- 目标会话冷扫和缓存重载均显示 `gpt-6.2-sol` 与 `gpt-6-luna` 两类用量。
- 片段交界处的重复事件只计一次；普通 / 压缩副本、父子 fork、增量追加和失败恢复回归通过。
- 冷扫与重载的所有模型桶一致，源日志内容、大小和修改时间不变。
- 历史候选片段逐组扫描并记录可确认影响范围；不能从现存日志证明的部分标注为未知。
- 文档检查、针对性自动化测试和全量测试通过。真实安装应用验收另行记录，不由自动化通过替代。

## 9. 依赖、约束与开放问题

- 依赖 Codex 本机日志中现存的会话标识、rollout 文件身份、模型上下文和结构化用量字段。
- 事件级重复识别必须使用最小结构化字段，不持久化对话正文。
- 历史影响只覆盖当前本机仍留存且成功读取的日志；删除或不可读的旧日志无法恢复。
