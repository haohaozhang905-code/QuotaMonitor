# Codex 压缩历史日志兼容产品规范

## 用户问题与目标

Codex 将旧会话保存为 `.jsonl.zst` 后，当前采集器只发现 `.jsonl`，导致“累计”历史缩短。本次恢复本机仍保留明确用量字段的历史统计，保持原有日期、模型、请求增量和 fork 统计口径。

## 需求

- **HIST-001**：会话目录与归档目录里的普通及 Zstandard 压缩日志均参与统计；不依赖用户额外安装解压程序。
- **HIST-002**：同一会话的普通/压缩副本、跨目录副本只统计一次；父子会话继承的历史仍按现有规则排除。普通日志存在时优先读取，以保留追加内容。
- **HIST-003**：源日志只读，不解压回源目录，不修改内容、修改时间或文件名；只持久化现有范围的用量缓存。
- **HIST-004**：缓存重载及普通→压缩→普通转换不重复累计；旧版增量缓存首次升级时从源日志重新校准，避免沿用历史累计偏差。损坏、截断或暂时不可读的压缩文件不得产生部分成功统计，有缓存时保留上次有效值，无缓存时报告来源读取失败。

## 范围与非目标

仅扩展 Codex 本地日志读取与去重。不修改 Claude 等来源、提醒、状态栏、应用身份或安装流程；不补估缺少用量字段的月份，不恢复已删除文件，不承诺账号全量统计。首轮仅开发与隔离验证；2026-10-18 用户后续明确授权替换安装、打开 TOKEN 累计页并核验历史与数字，正式缓存可由新版正常刷新重建，原始日志保持只读。

## 状态与验收

正常时累计范围包含所有成功解析的历史；失败时沿用既有来源失败/上次成功数据展示。验收包括普通与压缩等价、双副本及跨目录去重、fork、追加、格式转换、缓存重载、截断/损坏/读取失败、源文件不变，以及本机真实历史的隔离扫描。安装版累计页与重启后的验证结果见 [验收记录](acceptance.md)。

不新增界面或文案；继续遵循 [设计规范](../../docs/DESIGN_SYSTEM.md)。
