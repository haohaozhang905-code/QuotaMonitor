# 技术执行计划

## 复用与实现

复用现有 JSONL 分块、标记预筛选、请求增量及父子会话去重。官方 facebook/zstd 仓库维护中；核对 v1.5.7 的 single-file decoder 实现、流式 API 与 BSD 许可后，固定到提交 `f8745da6ff1ad1e7bab384bd1f9d742439278e99`。只随应用编译官方解码器和小型只读流包装，不调用 Homebrew 或外部进程。保留版权、来源、生成方式及二进制随附许可证。

1. `Vendor/CZstd`：官方流式解码器和文件读取包装，验证帧结束、校验和与连接帧，限制解码窗口内存。
2. `JSONLReader`：统一普通文件和解压流的分块行读取，支持仅读首行身份；压缩文件禁止字节游标续读。
3. `CodexSessionTokenClient`：发现两种格式，以会话 ID（缺失时按逻辑路径/标准 rollout 文件名）选择唯一文件，优先普通文件。压缩与普通同路径共用逻辑缓存键，缓存增加可选格式标志；压缩变化整文件重算。
4. 测试覆盖 HIST-001～004，文档更新来源与缓存语义。遵循 [设计规范](../../docs/DESIGN_SYSTEM.md)，无界面改动。

## 迁移、失败与回滚

沿用 V5 缓存容器与原路径；新增可选格式字段，缺失按普通文件处理。安装验收发现旧版缓存有 186,539 Token 残留偏差，因此增加可选 `aggregationRevision: 1`：缺失时禁止沿用旧汇总及字节游标，从源日志完整重算，成功后替换；读取失败仍保留 last-good 并重试。格式转换同样完整重算，不在旧汇总上重复追加。压缩读取失败丢弃局部解析结果；无 last-good 时使来源刷新失败，由 Store 保留上次成功快照。回滚代码可忽略新增可选字段，但会再次漏读压缩历史；源日志无迁移。

## 验证与交付

运行针对性测试、全量测试、构建、SDD 与安全检查。本机验证使用独立临时缓存，比较冷扫描/缓存重载结果，复核重复文件及 fork，检查历史源文件前后内容摘要与修改时间。仅输出聚合日期、文件数与用量，不落盘完整会话。

后续安装授权已于 2026-10-18 取得：先备份旧应用及缓存，以原身份组装、签名校验并原子替换 `/Applications/QuotaMonitor.app`。实际点击 TOKEN 页“累计”，核对起点；对正式缓存和无缓存冷扫的今日以前逐日总量构造稳定摘要比较，避免今日活跃写入造成假差异。退出并重新启动后再次核对。安装与回滚路径记录在 acceptance.md。
