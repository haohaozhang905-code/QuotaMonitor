# 提醒机制 V1.1 产品规范

## 1. 背景

QuotaMonitor 已能展示 Codex 额度、 Claude （ DeepSeek 路由） 下的共享余额和本机 Token 用量。用户在持续编码时不会一直打开主面板，容易错过「额度接近耗尽」、「窗口重置」、「重置机会到期」和「当日用量快速上升」等变化。

提醒机制需要在**数据可信**的前提下主动提示关键变化，同时控制重复通知和权限失败带来的打扰。

## 2. 用户与核心任务

### 目标用户

同时使用 Codex、Claude 或其他 AI 编程工具，并依赖额度和本地 Token 信息安排工作的个人开发者。

### 核心任务

> 用户无需持续盯着主面板，也能及时得知需要关注的额度、余额、重置机会和用量变化，并可从提醒进入对应页面确认详情。

## 3. 目标

- 在额度进入预警与危急档位时提醒；
- 识别额度窗口按时或提前重置；
- 在具有明确到期时间的重置机会进入最后 24 小时时提醒；
- 在 DeepSeek 共享余额和当日 Token 达到固定条件时提醒；
- 冷启动完成新鲜数据同步后补发当前有效事件；
- 同一事件在同一周期内只提醒一次；
- 系统通知不可用时保留应用内投递能力；
- 缺失、失败、扫描中、过期或旧缓存数据不产生新事件。

## 4. 非目标

- 自定义阈值、静默时段或分项开关；
- 提醒历史、逐条已读或云端同步；
- 根据 Token 推算账单或预算告警；
- 自动兑换重置机会、充值余额或切换路由；
- 对没有明确到期时间的重置机会推断到期日；
- 修改状态栏创建方式、Bundle ID、登录项或安装流程；
- 控制 macOS 通知样式、声音和通知中心保留时间。

## 5. 需求

### REM-001：额度分档提醒

- Codex 5 小时额度和周额度分别使用 30% 预警档与 5% 危急档；
- 显示值进入 30% 档时提醒一次，之后进入 5% 档可再次提醒；
- 冷启动直接得到 5% 及以下时，只发送危急提醒，并将 30% 档记为已处理；
- 额度从 5% 下降至 0% 时不增加第三档提醒；
- 5 小时与周额度的已提醒档位绑定已确认的补充周期；重置时间连续漂移不能重新触发。只有新鲜观测证明额度恢复，才开始下一轮分档判断；未观察到恢复的跨周期保持静默；
- 百分比采用与界面一致的四舍五入口径。
- 下拉框、概览额度数字、概览状态标签、顶部风险卡和应用内提醒统一使用同一分档：31%～100% 正常、6%～30% 需关注、0%～5% 高风险；
- 重置时间只作为事实信息展示，不参与额度颜色或风险等级判断；
- macOS 菜单栏与系统通知保留系统控制的外观，通过文字和图标表达等级。

### REM-002：额度重置提醒

- 5 小时与周额度分别识别按时重置和提前重置；
- 只有上一条新鲜观测低于 100%、当前恢复至 100%，并且新重置时间比旧时间至少推进 2 分钟时，才识别为额度重置；
- 开盖后若额度已被继续使用、当前低于 100%，不发送“已重置”；
- 当前观察时间接近或晚于旧窗口结束时间时属于按时重置；早于旧时间 2 分钟以上时属于提前重置；
- 额度连续显示 100% 时，服务端重置时间的后移只更新基线，不生成重置通知；
- 首条新鲜观测只建立基线，不生成重置通知；
- 同一轮同时识别两类额度重置时，只向用户投递周额度提醒；
- 已抑制的 5 小时事件仍应写入去重状态，避免下一轮补弹。

### REM-003：用户主动重置抑制

当同一轮新鲜请求同时满足以下条件时，静默更新基线：

- 可用重置机会数量减少；
- 5 小时额度显示 100%；
- 周额度显示 100%。

当前接口无法确认操作主体，因此 V1.1 不展示“谁执行了重置”。旧缓存不能参与这项判断。

### REM-004：重置机会到期

- 每个具有明确到期时间的机会，在剩余时间首次进入 0～24 小时时提醒；
- 多个机会分别投递，并按到期时间排序；
- 相同到期时间通过稳定序号分别去重；
- 已过期、无到期时间或本轮请求失败的数据不提醒；
- 应用在提醒窗口内首次启动时补发，错过整个窗口后不追发。

### REM-005：DeepSeek 余额

- 仅在 Codex 或 Claude 当前识别为 DeepSeek 路由时判断；
- CNY 余额低于 ¥5 时提醒一次；
- 余额恢复到至少 ¥6 后重新具备提醒资格；
- 两个工具共享同一余额时只生成一个事件；
- 非 CNY 余额不套用人民币阈值。

### REM-006：当日 Token 里程碑

- 至少一个 Token 来源处于可用状态时参与判断；
- 按用户 Mac 当前时区的自然日累计；
- 每达到 1 亿、2 亿、3 亿等整数亿级里程碑时提醒；
- 一次刷新跨越多个里程碑时只展示最高值，并将低档一并记为已处理；
- 文件变化后的合并刷新以首条变化事件为起点，后续连续写入不得反复推迟同一轮刷新；
- 扫描期间发生的新变化在当前扫描完成后合并补刷一次，不得取消正在执行的扫描；
- 次日重新计算周期。

### REM-007：数据新鲜度与冷启动

- 只有刚完成刷新且可以确认的新鲜数据才能产生新事件；
- 扫描中、失败、过期、缺失或沿用旧缓存的数据不能产生新事件；
- 冷启动先恢复显示快照，再等待新鲜数据完成同步后判断；
- Codex 额度与 DeepSeek 余额均需要刷新时并行请求，避免一个提醒等待无关来源串行完成；
- 刷新失败保留上一条有效基线，但不根据失败结果改变提醒状态。
- 从熄屏或锁屏恢复后先取得新鲜快照，只判断当前仍有效的事件；不重放离开期间的事件。

### REM-008：去重与持久化

- 每条规则使用稳定 ID 保存状态；
- 定时刷新和应用重启不得重复投递同一事件；
- 新额度窗口、余额恢复或新自然日按对应规则重新启用；
- 重置提醒以刚结束或被替换的旧窗口作为稳定事件身份；只有额度再次低于 100% 后才重新启用；
- 升级时将旧账本迁入 V4，并按上一条观测初始化重置提醒资格，避免 100% 状态在升级后补弹；
- 新的额度档位语义迁入 V5；当前低额度周期保守继承已提醒档位，已投递事件与被环境抑制的候选事件分别处理；
- 旧版本键保留供兼容和回滚读取。

### REM-009：投递与降级

- 总提醒开关关闭后停止判断，并关闭当前应用内提醒；
- 系统通知偏好开启且 macOS 已授权时，优先使用原生通知；
- 未授权、被拒绝、关闭或投递失败时，使用菜单栏下方的应用内卡片；
- 应用内卡片默认 8 秒后消失，悬停暂停倒计时；
- 点击提醒关闭当前卡片并进入对应页面；
- 多个事件使用独立通知或独立卡片，顺序保持稳定。
- 熄屏、系统睡眠、锁屏及状态未知时不投递任何类别的真实提醒；亮着的外接屏幕且会话已解锁时可以投递；投递前须再次核对状态。

### REM-011：离席静默与恢复

- 熄屏、系统睡眠或锁屏期间不判断提醒规则，不排队积攒提醒；展示数据可以继续刷新；
- 亮屏本身不代表解锁；确认回到可交互会话后，合并唤醒信号，刷新并只依据当前新鲜结果判断；
- 同批不同类别可以各投递一条，过期或已恢复的事件不补发；
- 锁定状态无法确认时暂缓投递，直到收到可信解锁信号或用户与应用交互。

### REM-010：安全与副作用边界

- 提醒不会自动兑换重置机会、修改路由或充值；
- 测试提醒不能写入真实去重账本或改变真实未读状态；
- 提醒功能不能改变状态栏身份、Bundle ID 或登录项。

## 6. 事件顺序

同一轮刷新按以下顺序处理：

1. 5 小时额度；
2. 周额度；
3. 5 小时额度重置；
4. 周额度重置；
5. 按到期时间排列的重置机会；
6. DeepSeek 余额；
7. Token 里程碑。

## 7. 体验状态

| 状态 | 用户体验 |
| --- | --- |
| 新鲜数据命中规则 | 投递对应提醒 |
| 数据扫描中 | 等待，不抢先提醒 |
| 刷新失败但有旧数据 | 保留旧显示，不生成新提醒 |
| 系统通知未授权 | 应用内卡片降级 |
| 多个事件同时命中 | 独立展示，保持稳定顺序 |
| 应用重启 | 恢复账本，避免重复投递 |
| 熄屏、睡眠或锁屏 | 不判断规则，不提交系统通知，不显示应用内卡片 |
| 解锁后 | 刷新并判断当前有效事件，不重放历史通知 |

应用内提醒的颜色、字体、尺寸、交互、可见区域、无障碍和视觉验收遵循 [`docs/DESIGN_SYSTEM.md`](../../docs/DESIGN_SYSTEM.md#84-提醒卡片)。系统通知的外观由 macOS 管理，标题与事实语义仍需与应用内提醒一致。

## 8. 验收标准

- `REM-001` 至 `REM-011` 均能追踪到实现与测试；
- 阈值、冷启动、去重、恢复线、跨档、重启和账本迁移有自动化测试；
- 中英文提醒标题和正文均有对应资源；
- 系统通知授权、拒绝和应用内降级路径有验证证据；
- 应用内卡片在主屏和多屏环境中处于可见区域；
- 深色与浅色、单卡片与多卡片、点击和自动消失完成真实应用验收；
- 构建或单测通过不能代替最后两项真实界面验收。

详细场景和当前证据状态见 [acceptance.md](acceptance.md)。

## 9. 依赖与约束

- 依赖额度、余额、重置机会和 Token 来源提供明确的新鲜度；
- macOS 系统通知权限由系统管理；
- 提醒规则不能提高数据源读取频率来制造实时性；
- 数据定义与覆盖范围遵循 [`docs/DATA_SOURCES.md`](../../docs/DATA_SOURCES.md)。

## 10. 版本边界

V1.1 固定上述规则。自定义阈值、静默时段、预算告警和提醒历史需要新的 Spec，不能直接扩进本版本。

本文件由现有产品设计、代码和测试重建。更详细的历史规则说明见 [`docs/REMINDER_PRODUCT_DESIGN.md`](../../docs/REMINDER_PRODUCT_DESIGN.md)，技术实现见 [plan.md](plan.md)。
