# 输入缓存命中展示产品规范

## 1. 背景与核心任务

Token 总量包含模型重复读取的历史、文件和工具结果。用户需要知道输入中有多少来自缓存，理解大用量的组成；目前尚无面向用户的缓存摘要，也无法从已有默认零值判断字段是否缺失。

核心任务：用户在概览与现有看板指标中看懂输入缓存命中情况，在既有用量条中感知命中输入的组成，并通过点击问号核对分母、覆盖范围和未统计原因。对于已确认 `inputTokens` 只代表未命中输入的 DeepSeek Harness，现有 Token 输入总量也需规范化为未命中 + 缓存读取 + 缓存写入，避免缓存 Token 从总量中漏计。

2026-11-04 用户确认分阶段推进；首轮图片审稿后明确修订为“概览比较数字后内联、顶部六指标、复用平台 / 模型用量条、问号点击弹框”，并确认第二版设计、授权开始实现。旧独立容器方案已归档为 [superseded 设计稿](design-v1-superseded.md)。当时尚未授权安装、提交与推送；后续授权及各版安装事实按时间记录于 [验收记录](acceptance.md)。

## 2. 阶段、目标与非目标

- **阶段 A（本规范）**：输入缓存命中量、按输入 Token 加权的命中率、明细覆盖与状态解释。
- **阶段 B（deferred）**：API 参考估值。另建独立 Spec / Plan；本规范完成不自动启动或授权价格实现。此前聊天中的价格白名单和界面提案仍是讨论材料，不是本阶段验收要求。

本阶段不做金额、节省金额、会员回本率、价格目录、汇率、缓存优化建议、命中率提醒、模型评分或命中率历史图；不新增远程请求、权限、凭据读取或依赖。不修改菜单栏、下拉框、额度、余额续航、登录项和安装流程。

保持其他来源现有 Token 主指标与图表口径；DeepSeek Harness 按已核实的上游字段定义修正输入总量，cc-switch 沿用其 `input_token_semantics` 对应的既有总量口径。缓存率只使用字段含义明确、通过一致性校验的新鲜数据。

## 3. 来源准入（CACHE-001）

以下是**计划接入范围**，不是已实现或已完成真实验证的支持声明。来源按格式与字段语义准入，不按模型价格白名单准入；模型为 unknown 本身不妨碍核实缓存。

| 来源 | 本阶段安排 | 准入条件 |
| --- | --- | --- |
| Codex 普通 / 压缩会话 | 接入 | 能核实真实输入与缓存读取字段；累计差分两端均有适用证据，并沿用现有 fork / 副本去重结果 |
| Claude Code 本地 transcript | 接入 | 普通输入、缓存读和缓存写的字段含义与缺省规则可核实；统一输入包含三部分 |
| WorkBuddy generation JSONL | 接入 | 只用实际 generation usage 内明确的输入与缓存读取；保留 JSONL 优先和 trace 去重 |
| WorkBuddy 旧 JSON 汇总 | 暂不纳入 | 当前含缺失字段回退和汇总模型；本阶段不扩大格式核验范围 |
| DeepSeek Harness | 接入 | v4 usage 的 `inputTokens` 是未命中缓存输入；`cacheReadTokens` / `cacheWriteTokens` 是独立桶。按三者之和作为输入总量；校验单条非负与加总溢出 |
| Claude Desktop / cc-switch | 接入 | 读取 `input_token_semantics`，只转换已知语义：0=已含缓存读取、未含缓存创建；1=输入已含读取和创建；2=普通输入，需加读和创建。未知语义不参与缓存率 |
| Qoder、Kimi 与其他通用来源 | 暂不纳入 | 继续原有 Token 展示，缓存明细标为本阶段未接入 |

工具与路由分开：通过上述合格来源调用其他模型的记录，只有实际 usage 满足准入才参与；不把 DeepSeek 路由再作为独立工具相加。模型名、会员身份和路由名称都不能替代字段证据。

字段省略只有在该来源格式有已核实的“省略即零”约定时才能按零处理；否则表示未知。不得凭旧缓存默认值恢复字段存在性。

## 4. 计算与单位（CACHE-002）

对通过准入和一致性检查的用量，定义：

```text
I = 输入总量（包含普通输入、缓存读取和缓存写入）
R = 缓存读取 / 命中的输入 Token
W = 缓存写入 Token（若该格式适用）
O = 输出 Token

输入缓存命中率 = ΣR / ΣI
缓存命中量 = ΣR
其他输入 = ΣI - ΣR（包含新输入与缓存写入）
```

- 分母不含输出；不把缓存写入算成缓存命中；不重复加入推理 Token。
- 先核实单条计量记录，再相加；不能让一条异常记录被其他正常记录的数值掩盖。
- 不平均会话、日、工具或模型的百分比。例：90/100 与 10/900 汇总为 100/1000 = 10%，不是 50%。
- I=0 时命中率不可计算，显示“无可计算输入”；I>0 且 R 明确为 0 时显示 0%。
- 所有分项必须非负，R≤I；W 适用且明确时还须满足 R+W≤I。违反时排除缓存统计，不通过 clamp 修补。
- `total_tokens` 被用作现有输入字段承载值、但无法拆出真实输入的记录，不作为缓存率分母。
- 率保留一位小数，0% / 100% 仅用于真实边界；接近边界的非边界值显示 <0.1% / >99.9%，不舍入成已全部命中或完全未命中。

## 5. 覆盖、时间与新鲜度（CACHE-003）

命中率只描述合格输入，不能在部分覆盖时声称代表所有平台。

```text
明细覆盖率（按总 Token） = 合格记录的 Σ(I+O) / 同周期看板已采集的总 Token
```

分子、分母来自同一展示快照、同一时间窗口及相同去重口径。覆盖率包含输出只为衡量记录覆盖，和以输入为分母的命中率含义不同；详情必须显示两个公式的简短解释。分母也包含本阶段未接入、字段缺失和沿用缓存等记录当前可展示的 Token，不代表账户全量。来源读取失败可能遗漏尚未采集的数据，必须另行标记，不能由覆盖率推出数据完整。

- 只要存在未纳入的正用量或相关来源失败，问号弹框内必须标“部分数据”；不能因舍入显示 100% 而去掉状态。默认页面不另加部分数据徽标或覆盖率说明行，问号按钮的辅助功能描述包含当前状态。
- 没有合格输入时不显示 0% 或空的组成条；显示原因及来源明细。
- 概览使用今日，本地自然日 00:00 至当前；Token 看板沿用近 7 / 30 / 90 日与累计。没有可靠事件时间的记录不参与周期缓存统计。
- 首次扫描没有有效结果：显示“正在读取缓存明细”。再次刷新时可保留上次完整摘要并明确“正在更新 / 上次时间”。
- 刷新结束后，失败、过期或使用 last-good 文件内容的贡献不参与本次新鲜命中率。其上次值可在详情单独展示，标“上次记录”与时间，不与新鲜分项相加。
- 旧历史在本次成功扫描后可以有效；历史事件时间早不等于采集结果过期。冷启动只有旧缓存、尚未成功扫描时不能当作新鲜结果。

## 6. 概览内联指标与说明弹框（CACHE-004）

在今日 Token 主数字所在行，将缓存指标放在原有昨日比较和涨跌幅后方：

> 497万　较昨日 1218万　↓59.2%　｜　输入缓存命中 80.0%　(?)

以上为示意值。缓存标签和数值采用辅助指标字号，不增加独立行、容器、命中数量或状态徽标，不改变原有三项辅助指标。正常窗口保持同一基线；最小窗口优先压缩组间留白，实在放不下时仅允许缓存组整体换行，不能截断百分比或缩小主数字。

点击问号打开锚定按钮的原生说明弹框，直接显示**今日**范围、命中量、已核实输入、命中率、明细覆盖、部分 / 过期状态、更新时间与未纳入原因。不再跳转到 Token 看板；消除原方案中的“今日局部范围 / 跟随看板”额外状态。点击外部或 Esc 关闭，焦点回到按钮。交互见 [设计说明](design.md)。

## 7. Token 六项指标与复用用量条（CACHE-005、CACHE-006）

- 顶部现有灰色指标条由五项变为六项，依次为：总 Token、日均 Token、峰值日 Token、主要平台、主要模型、输入缓存命中。第六项显示百分比及问号，范围始终跟随现有近 7 / 30 / 90 日或累计。
- 不新增输入缓存容器、展开区、来源表或缓存导航页，不移动趋势图来容纳缓存解释。
- 平台用量和模型用量沿用原行、排序、总 Token 数和右侧用量占比。两个标题行各提供缓存颜色图例和点击问号；行本身可点击 / 键盘打开该工具或模型的具体缓存说明，不增加一整列百分比。
- 原已填充条长继续表达该项总 Token 占比；其内部用统一蓝灰色标出**可核实缓存命中输入量**，其余保持原条色。全长轨道仍为该组总量参照。

```text
Tj = 某行全部已采集 Token，G = 当前分组全部 Token
Rj = 该行有合格证据且新鲜的缓存命中输入
Lj = 原已填充条长

原用量占比 = Tj / G（条长和右侧百分比保持此含义）
蓝灰段占该行已填充条的比例 = Rj / Tj
该行输入缓存命中率 = Rj / 合格输入 Ij（在点击弹框中显示）
```

不能直接把输入命中率 Rj/Ij 乘进表示总 Token 的原条长。例：I=100、R=80、O=100，则输入命中率 80%，蓝灰段只占该行总 Token 200 的 40%。

- 其余条段称“其余 Token（含输出与未核实部分）”，不得称为全部“缓存未命中”。部分来源 / 格式缺字段时，只着色已核实命中，弹框明确部分覆盖；无缓存证据保留原条色，弹框显示“未知 / 未纳入”，不能显示 0% 或全部未命中。
- 真正 R=0 与没有证据在颜色上都可能没有蓝段，必须能通过点击 / 键盘说明和辅助功能区分。极小命中不强行设置最小蓝段宽度。
- 模型行及“其他”行按现有分组成员合并原始贡献后计算，不平均来源命中率，不加入新模型筛选或价格白名单。
- 旧格式、缺字段、语义待核实、异常、时间未知、旧缓存和刷新失败的原因保留在相应弹框内；不因默认页面收起说明而丢失数据。
- 本阶段只改既有排行条的内部组成，不增加趋势图缓存堆叠或热力图模式。

## 8. 交互、视觉与无障碍（CACHE-007）

遵循 [项目设计规范](../../docs/DESIGN_SYSTEM.md)，详细层级、线框、文案与状态见 [design.md](design.md)。采用现有实色卡片、字体、间距和主题 Token。命中率是组成事实，不设红绿阈值、达标标签或“越高越好”的评分。

所有字段、状态和公式说明同步中英文。Tab 可到达问号及可操作排行行，Enter / Space 打开弹框、Esc 关闭，VoiceOver 能读出范围、命中量、分母、率、覆盖及异常；不依赖颜色或 hover。支持减少动态效果与最小 820×540 pt 主窗口。六格标题可适当换行，数值保持同一基线；最小窗口仅收紧指标内边距和长模型字号，不改成新的六张卡。

## 9. 数据与兼容边界（CACHE-008）

- 原始日志只读；保留现有总 Token、fork / trace 去重、压缩格式选择、追加边界和 last-good 行为。
- 新增缓存证据不得改变既有 Token 累计和提醒事实，也不得触发新提醒。
- 旧缓存缺少字段证据时，显示“旧缓存待重扫”；成功重扫后恢复缓存能力，重扫失败仍保留原 Token 数字。
- 发现其他来源 Token 口径问题时记录为后续独立修正，不能顺带重算或迁移该来源总量。
- 不涉及新网络、遥测、账号或凭据读取；不安装、替换或发布应用。

## 2026-11-08 来源语义核实及准入更新

本节覆盖先前“Claude Desktop / Harness 未纳入”的来源矩阵及第二次交互审稿末条：

- DeepSeek Harness 的“缓存读取大于 inputTokens”源于字段定义：`inputTokens` 仅为未命中缓存输入，read/write 单独记录；`usage.totalTokens` 按三类输入桶加输出计算。正确缓存输入总量为 `inputTokens + cacheReadTokens + cacheWriteTokens`，命中率为 read / 该输入总量。禁止把 read 截断到 raw input。
- Claude Desktop 的 cc-switch 数据按 `input_token_semantics` 归一：0 legacy 是 raw input 已含 cache read、未含 cache creation；1 已含 read 与 creation；2 fresh 不含任一缓存桶。只让已识别语义且字段一致的记录进入缓存测量。
- 原始 Token 总量仍是 inclusive input + output；两个来源的 cache read/write 明细不重复加到总量。
- 未知 Harness 缓存字段或 cc-switch 未知 / 缺失 semantics 保留原有 Token 展示，但排除缓存命中测量；不显示成 0%。
