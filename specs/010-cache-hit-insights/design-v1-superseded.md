# 输入缓存命中：交互与视觉设计草案

> 对应 QMT-010；状态：draft / 未实现、未视觉验收。用户已确认“概览一行摘要，Token 看板展开明细”。

## 1. 设计任务与依据

模式为 Operate：用户工作间隙快速理解用量组成，再按需核对数据。沿用现有 macOS 原生窗口与 `docs/DESIGN_SYSTEM.md` 的实色内容卡、等宽数字及中性图表，不做整体改版。

现有视觉依据：`OverviewPageView.overviewHeroCard` 的 34 pt 主数字和辅助指标；`TokenPageView` 的五格指标、周期控件及趋势图；`PanelTheme` 的 surface / text / chart 系列。以下是线框与实现约束，不是现有运行界面截图。

规划工具说明：impeccable 上下文脚本未自动识别本仓库 SwiftUI 视觉实现，并提示 PRODUCT.md 未采用其新版模板；已以实际代码与项目设计规范为准。模板迁移属于该技能的 init 工作，不是本次功能规划的前置条件，也未在本轮执行。

## 2. 信息顺序与概览线框

```text
今日 Token
16M                     昨日 … / 比较 …（原有内容）
输入缓存命中 80.0% · 8M Token · 部分数据   查看明细 ›
仅已核实输入                                  （部分时出现）

近7日总量               今日占比              主要模型
…                       …                     …
```

示意数据：合格记录输入 10M（命中 8M，其他输入 2M）、输出 2M；另有未纳入来源 4M，总 Token 16M，明细覆盖 12/16=75%。线框不使用本机真实会话或身份信息。

- 正常宽度尽量保持摘要一行；只有“部分数据”时追加一条短限定语，窄窗口允许摘要换行。
- 今日 Token 仍是视觉焦点。缓存行采用 11–12 pt 常规文字、等宽百分比；不放大成第二个 Hero，不替换原指标。
- “查看明细”是明确的文本按钮，保留焦点态；整张 Hero 不变成隐形链接。
- 未知状态显示“缓存明细待核实 · 查看原因”，不显示空进度条或伪零。

数据表按稳定工具 / 客户端顺序展示，不按命中率排“好坏”。未知模型无需额外醒目标签，因为本阶段不依赖模型定价。来源的一部分缺字段时，该行显示有效子集并标“部分”；原因可多行展示，无 hover 依赖。

### 从概览进入的今日范围

缓存区展开并聚焦标题，显示：

> 输入缓存 · 今日（来自概览）　[跟随看板：近7日]

其余图表仍显示各自原有范围。点击“跟随看板”或主动改变看板周期后，缓存区恢复跟随；收起再展开不暗中切换范围。回到概览再点击入口，重新显示今日。只展开不发起额外扫描。

### 为什么选择原位展开

用户可以保留 Token 总量上下文；一个缓存细分不值得增加导航页、模态窗或多层弹窗。代价是展开后趋势图会下移，因此默认收起，正常收起布局只占紧凑的两行信息；不要把每个工具变成独立卡片。

## 4. 状态视觉

| 状态 | 摘要与明细 |
| --- | --- |
| 完整有效 | 正常百分比与数量；详情显示覆盖和分母 |
| 部分 | 数字旁持续显示“部分数据”；详情列未纳入原因，不能只用黄点 |
| 合法零命中 | 0%；文字明确命中 0，组成条全为其他输入 |
| 无输入 / 无记录 | “无可计算输入” / “当前范围暂无记录”，不画组成条 |
| 首次读取 | “正在读取缓存明细”；保留稳定区块，不播放数字增长动画 |
| 后续更新 | 上次结果加“正在更新 · 上次时间”，随后同批切换 |
| stale / last-good | 不放入新鲜合计；对应来源详情为“上次记录 … / 时间”，或仅显示待更新原因 |
| 异常 / 旧证据 | “用量口径异常” / “旧缓存待重扫”；不强行压到 100% |

命中率和覆盖率本身使用 text；chartPrimary 表示命中，chartNeutral 表示其他输入，separator 保持边界。不得套用绿色达标、红色低命中或上升奖励。warn 只用于数据过期 / 缺失等状态文字，不能把事实率映射成风险。

## 5. 文案、响应尺寸及无障碍

中英文拟用名称：

| 中文 | English |
| --- | --- |
| 输入缓存 | Input cache |
| 输入缓存命中 | Input cache hit rate |
| 命中量 | Cached input tokens |
| 其他输入 | Other input |
| 已核实输入 | Input with verified cache data |
| 明细覆盖（按总 Token） | Detail coverage (by total tokens) |
| 部分数据 / 仅已核实输入 | Partial data / Verified input only |
| 口径待核实 / 旧缓存待重扫 | Semantics unverified / Rescan needed |
| 查看明细 / 查看原因 / 跟随看板 | View details / View reasons / Follow dashboard |

- 最小窗口时摘要换行，来源行改为工具标题＋带标签的数值两行，不通过压缩关键字号塞进宽表。来源名与原因允许换行，数值与单位不截断。
- 复用 24 pt 卡片圆角、16 pt 内边距、14 pt 区块间距；不新增公共颜色、材质或投影。
- 窄窗口组成条仍有完整文本图例；比例 0 / 100 时不设最小填充宽度，微小命中靠文本表达，避免伪造面积。
- Tab 按页面顺序访问入口、范围恢复和展开按钮；Enter / Space 操作；展开焦点留在触发按钮，导航进入时焦点到缓存标题。收起不能把焦点遗留在隐藏行。
- VoiceOver 摘要示例：“今日，输入缓存命中百分之八十，命中八百万 Token，基于已核实输入一千万，部分数据”；详情另读明细覆盖、分母和上次时间。
- 减少动态效果时直接切换；普通模式最多沿用短淡入，不为百分比做计数或条形增长动画。

## 6. 待验清单与后续阶段
